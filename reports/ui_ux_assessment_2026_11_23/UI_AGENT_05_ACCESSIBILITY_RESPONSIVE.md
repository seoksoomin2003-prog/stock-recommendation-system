# UI/UX 평가 2026-11-23 — 에이전트 5: 접근성과 반응형

작성: 접근성·반응형 담당 (읽기 전용 점검). 대상: 퀀트 터미널 웹 화면 (`terminal/static/`).
기준: WCAG 2.2 AA, 다섯 뷰포트 1920×1080 · 1440×900 · 1280×800 · 768×1024 · 390×844.

## 요약

- 화면은 다섯 폭 모두에서 **페이지 전체가 옆으로 밀리지 않고**(조정자 측정: overflow-x 없음) 깨지지 않습니다. `lang="ko"`, header/nav/main/footer 랜드마크, 입력창 `aria-label`, 순위 행의 키보드 펼치기(Enter/Space, `aria-expanded`, `:focus-visible`), 상태 막대의 `role=status`/`role=alert`, 터치 화면 40 px 버튼 같은 기본기는 들어 있습니다.
- 그러나 AA 기준으로는 **통과하지 못합니다.** 가장 큰 세 가지:
  1. **사용자가 실제로 쓰는 어두운 테마에서 흰 글자 + `--accent`(#6d9bff) 대비가 2.70:1** — `조회`, `묻기`, `평가` 버튼과 **선택된** 세그먼트(미국/한국, 스윙/장기, 오늘 순위 …)가 모두 이 조합입니다. 선택 상태일수록 글자가 덜 읽힙니다.
  2. **마우스로만 열리는 곳**: 점수 탭 `추적·검증`의 접힌 구역 제목(h2 클릭), 관심종목·동종업계·검색 결과 행(`tr.click`), 시장 개요 카드(`div.card[data-ticker]`), 히트맵 캔버스 — 키보드 Tab으로 닿지 않습니다.
  3. **상태가 보조기기에 전달되지 않음**: `role=tablist`인데 탭 역할·`aria-selected`가 없고, 세그먼트 버튼에 `aria-pressed`가 없고, 명령창은 `role=dialog`이지만 모달·포커스 가둠·선택 항목 알림이 없습니다.
- 반응형의 약점은 **768 태블릿**(표 축소 기준이 760 px이라 데스크톱 표가 그대로 들어가 판정·근거 열이 잘림)과 **390 휴대폰**(머리글 약 415 px, 순위 표가 약 8,790 px 아래에서 시작, 옆으로 미는 표 13개)입니다. 1920에서는 본문이 1280 px로 묶여 약 640 px가 빈칸입니다.
- 제안 점수: **Accessibility 4.5 / 10**, **Responsive 2.5 / 5**.

## 뷰포트별 평가

### 1920 × 1080 (32, 33)
- `main { max-width: 1280px }`(`style.css:68`) 때문에 패널 1248 px, 양옆 약 640 px 빈칸(EVIDENCE D5). 800 px로 줄인 스크린숏에서는 글자가 매우 작게 보임 — 화면이 넓을수록 "같은 내용을 작게 보는" 셈.
- 넘침·잘림 없음, 순위 표 전 열 보임. 문장이 긴 설명 영역은 폭 제한이 오히려 읽기에 좋으므로, 제한을 푸는 대상은 **표 화면(순위·스크리너·주문 계획)**으로 한정하는 것이 맞음.
- 평가: 기능 통과, 공간 활용 미흡.

### 1440 × 900 (01, 18, 22, 28, 29)
- 기준 폭. 순위 표 13열 모두 보임, 두 점수 카드 나란히, 오늘 탭 후보 두 표 나란히. 넘침 없음.
- 문제는 테마 대비(어두운 accent 위 흰 글자, 밝은 up/warn)와 키보드 경로이지 배치가 아님.
- 평가: 양호.

### 1280 × 800 (34)
- 순위 표가 가로 스크롤 없이 들어감(측정: 옆으로 미는 표 0). 오른쪽 "가점 / 감점" 열이 화면 끝에 붙음 — 여유가 거의 없음.
- 높이 800에서 sticky 머리글(약 52 px)+묶음 탭이 남는 세로 공간을 조금 줄임. 큰 문제 아님.
- 평가: 양호.

### 768 × 1024 (35, 36, 37)
- 핵심 문제: 표 축소 규칙이 `@media (max-width: 760px)`(`style.css:437`)이라 768에는 적용되지 않음. 그래서 순위 표는 데스크톱 13열 그대로, **판정 알약이 "매수 후"에서 잘리고 진입·가점/감점 열은 화면 밖**(36). 오늘 탭 후보 표도 "가점/감점" 열이 잘림(35). 세로 1024 태블릿에서 가장 중요한 열이 숨는 구조.
- 머리글이 두 줄(⌘K·◐가 둘째 줄)이고 600 px 초과라 sticky 유지 → 약 105 px가 항상 위를 덮음. 표의 열 제목 행은 sticky가 아니라 스크롤하면 열 이름이 사라짐(36).
- 종목 화면(37)은 잘 접힘: 지표 4열 격자, 차트 전체 폭.
- 평가: 부분. 가장 개선 효과가 큰 폭.

### 390 × 844 (38, 39, 40)
- 좋음: 터치 대상 40 px 이상(`pointer: coarse` 규칙), title 있는 요소에 점선 밑줄로 "누르면 설명" 신호(38), 오늘 탭 숫자 타일 2열, 머리글은 600 px 이하에서 sticky를 풀어 스크롤로 사라짐(`style.css:385`), 표 첫 열 sticky(`style.css:90`)로 옆으로 밀어도 종목명 유지.

## 강점

- `<html lang="ko">`, 랜드마크(header 1, nav 2, main 1, footer 1), 주요 입력창 `aria-label`, 시장·보기 묶음 `role=group` + `aria-label`.
- 순위 행은 모범 사례에 가까움: `tabindex=0`, Enter/Space로 펼치기, `aria-expanded` 갱신, 대비 5.65의 `:focus-visible` 윤곽(`qsf.js:443,492-499`, `style.css:415`).
- 색만 쓰지 않는 습관: `+`/`−` 부호, ▲▼, 색 점 + 판정 글자, 등급 글자, "색은 항상 글자 옆에 둔다"는 주석(`style.css:149`).
- 어두운 테마의 글자 토큰(ink 14.21, muted 5.70, up 7.31, down 5.96, warn 8.35)은 모두 통과.
- 터치 환경: 40-42 px 최소 높이, hover 대신 `#taptip` 설명 막대, title 요소의 점선 밑줄 — 휴대폰 사용을 실제로 고려한 흔적.
- 다섯 폭 모두 페이지 가로 넘침 없음, 표는 `.tbl-wrap`으로 따로 스크롤, 첫 열 sticky.
- 수집·네트워크·버전 막대에 live 영역 설정.
- 차트분석 "지금 상태" 문장, 비교 기간 표, FC-1 `role="img"` 요약 등 그림에 글 설명을 붙인 곳이 이미 있음.

## 점수 제안

**Accessibility: 4.5 / 10**
- 더한 점: 언어·랜드마크·레이블의 기본기, 순위 행 키보드 처리, 색+부호 이중 표기, 어두운 테마 글자 대비, 터치 대상 크기, 일부 live 영역.
- 뺀 점: 사용자의 실제 테마에서 주 버튼·선택 상태 대비 2.70(1.4.3 실패), 접는 구역·표 행·카드의 키보드 불가(2.1.1 실패), 선택 상태가 보조기기에 전혀 전달되지 않음(4.1.2 실패), 차트 글 대체 부족, 입력 윤곽 대비, 초점 표시를 브라우저 기본에 의존.
- 한 사람이 마우스로 쓰는 도구라 실제 피해는 작지만, AA 기준 점수로는 절반 아래가 정직합니다. A1·A3·A5만 고쳐도 6점대가 가능하다고 봅니다.

**Responsive: 2.5 / 5**
- 더한 점: 어느 폭에서도 깨지거나 페이지가 옆으로 밀리지 않음, 1280-1440은 양호, 종목 화면은 768에서 잘 접힘, 휴대폰 터치 대응.
- 뺀 점: 768 태블릿에서 핵심 열이 잘림(기준 폭 760), 휴대폰에서 순위가 약 8,790 px 아래, 머리글 약 415 px, 1920에서 약 3분의 1이 빈칸, 기준 폭 5종이 섞여 중간 상태가 생김.

## 확인하지 못한 것

- 화면 낭독기(VoiceOver, NVDA) 실제 실행 — 4.1.2·4.1.3 판단은 코드 기준 추론.
- 실제 키보드 Tab 순회와 브라우저별 기본 초점 윤곽 모양, Mac Safari의 "Tab으로 모든 항목 강조" 설정 영향.
- 200 % 확대(1280 폭에서 약 640 css px)와 320 css px 폭 리플로 — 코드상 640 px에서는 sticky 머리글이 2-3줄로 높이 약 400 css px 화면의 상당 부분을 덮을 가능성이 있으나 미측정.
- 텍스트 간격 덮어쓰기(1.4.12) 시험.
- 2.4.11 초점 가려짐은 위험만 확인, 실제 가려짐은 미확인.
- 실제 휴대폰·태블릿 기기(조정자 측정은 데스크톱 Chromium의 뷰포트 흉내). 가로 방향(844×390, 1024×768)은 측정 없음.
- 밝은 테마의 768·390 화면, 한국 시장 화면의 휴대폰 배치.
- 색각 이상 시뮬레이션(녹·적 캔들, 히트맵)은 하지 않음 — 위 1.4.1 판단은 색 외 신호의 유무만 본 것.
