# 디자인 방향 제안 (2026-11-23)

작성: 총괄 디자인 평가자. 이 문서는 제안이며, 소유자가 승인하기 전에는 아무것도 바꾸지 않습니다. 점수·공식·기준·진입/청산·포트폴리오 규칙은 다루지 않고 **표시만** 다룹니다. 빌드 없는 vanilla JS 구조를 유지하고 휴대폰에서 같은 파일이 동작해야 한다는 조건을 지킵니다.

## 1. 어떤 방향인가

### 1.1 사용자 조건

| 조건 | 디자인에 주는 요구 |
|---|---|
| 한 사람이 씀, Mac과 휴대폰 | 여러 사람을 위한 설정 화면·권한 구조는 필요 없음. 폰 배치가 Mac 배치만큼 중요 |
| 한국어 UI, 미국·한국 두 시장, 토스증권 사용 | 한국어 줄바꿈(keep-all), 한국 종목은 이름이 먼저, 색 관례는 사용자 선택 |
| 무료 공개 자료(지연) | 출처·받아온 시각·미확정 표시를 지금처럼 유지 |
| **점수가 예측력으로 검증되지 않음** | 불확실성 표시가 장식이 아니라 **필수 요구**. 확신을 주는 시각 요소의 크기를 불확실성 표시와 맞춰야 함 |
| "무료 자료로 Bloomberg처럼" | 넓은 화면에서 촘촘한 표, 키보드·명령창, 한 줄 상태 띠 |

### 1.2 다섯 방향 비교

| 방향 | 특징 | 이 사용자에게 맞는 점 | 맞지 않는 점 | 평가 |
|---|---|---|---|---|
| Bloomberg식 고밀도 터미널 | 검은 바탕, 고정 폭 글꼴, 여러 패널 동시, 기능 코드 | ⌘K 명령창이 이미 있음. 넓은 화면 활용 | 폰에서 불가능. 불확실성 문장을 놓을 자리가 없음. 밀도가 확신처럼 보임 | 부분 채택(표 화면만) |
| Koyfin식 모던 리서치 | 요약 띠 + 카드 + 탭, 통일된 숫자 서식, 사용자 열 선택 | 위계가 분명, 폰으로 접기 쉬움, 지금 구조(패널·카드)와 가장 가까움 | 그대로 쓰면 넓은 화면에서 성김 | **골격으로 채택** |
| FactSet식 기관용 | 한 장 tearsheet, 각주와 출처 중심, 보수적 색 | 출처·각주 중심 문화가 이 앱과 같음 | 기관 보고서 형식은 폰과 매일 확인에 무거움 | 종목 상세의 요약 띠에만 참고 |
| 미니멀 | 숫자 몇 개와 큰 여백 | 폰 첫 화면에 좋음 | 정보가 이 앱의 핵심. 경고·출처를 줄이면 정직성이 약해짐 | 오늘 탭 상단에만 참고 |
| **하이브리드** | Koyfin 골격 + 표 화면의 터미널 밀도 + 불확실성 우선 규칙 | 위 장점을 화면 종류별로 나눠 씀 | 규칙이 많아 문서화가 필요 | **추천** |

### 1.3 추천: "정직한 하이브리드"

**Koyfin식 모던 리서치 골격 + 순위·스크리너·시장 개요·차트분석에만 터미널 밀도 + 모든 점수에 '불확실성 우선' 표시 규칙.**

이유:
1. 지금의 패널·카드·배지 부품을 버리지 않고 위계만 세우면 되므로, 빌드 없는 구조와 약 24개 테스트 파일의 수정 비용 안에서 할 수 있습니다.
2. 요약 띠 + 접힘은 폰에서 그대로 한 열로 내려옵니다. Bloomberg식 다중 패널은 폰에서 쓸 수 없습니다.
3. 검증되지 않은 점수를 다루는 도구에서 "밀도 = 권위"는 위험합니다. 밀도는 표 화면에서만 쓰고, 점수가 나오는 곳에는 검증 상태를 같은 크기로 붙입니다.
4. 사용자가 원하는 "Bloomberg 느낌"은 한 줄 상태 띠, 명령창, 넓은 화면의 촘촘한 표, 키보드 이동으로 충분히 냅니다.

## 2. 색

### 2.1 원칙
- **의미가 다른 색은 token도 다르게.** 지금은 초록 하나가 상승·매수 후보·점검 통과·실데이터·찬성 논거를 모두 뜻합니다.
  - 가격 색 `--price-up/--price-down`: 가격·수익률 등락에만 씁니다.
  - 판단 색 `--judge-*`: 앱의 판단 알약에만 씁니다.
  - 상태 색 `--status-*`: 자료·점검 상태 배지에 씁니다.
- 색은 지금처럼 늘 글자·부호 옆에 둡니다(style.css:149 원칙 유지).
- 오르면 나쁜 지표(VIX, 금리, 달러인덱스) 타일은 중립색 글자 + 부호를 씁니다.

- `--status-ok`를 중립으로 두는 이유: "과거 점검 통과"는 범위 폭의 점검이지 방향 검증이 아니므로 승인색을 쓰지 않습니다.

### 2.3 상승 빨강 문제 — 소유자가 고를 일

지금은 한 쌍의 전역 token(`--up` 초록, `--down` 빨강)을 두 시장이 함께 씁니다(style.css:3, 12, 21). 토스증권을 포함한 국내 화면은 빨강이 상승·파랑이 하락입니다. 부호(+/−)가 늘 붙어 있어 치명적이지는 않지만 두 앱을 오가면 빨강의 뜻이 반대가 됩니다. **결함이 아니라 선택입니다.** 세 가지 안:

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 그대로 (국제식) | 두 시장 모두 초록 상승 | 변경 없음, 미국 화면 관례와 같음 | 토스 화면과 반대 |
| B. 한국식 전체 | 두 시장 모두 빨강 상승·파랑 하락 | 토스와 같음, 한 규칙 | 미국 자료 화면 관례와 다름 |
| C. 시장 따라 | 한국 시장 선택 시 한국식, 미국은 국제식 | 각 시장의 관례 | 같은 화면에서 두 시장을 볼 때(통합 계좌) 규칙이 섞임 |

한국식 값(제안): 밝은 `--price-up` #c22f35(흰 5.60, chip 4.94), `--price-down` #1f5fd1(흰 5.81, chip 5.13); 어두운 `--price-up` #ff6369(panel 5.96, chip 5.25), `--price-down` #5b9cff(panel 6.30, chip 5.55).
주의: 어두운 테마에서 하락 파랑 #5b9cff와 `--accent` #6d9bff가 거의 같습니다. B·C를 고르면 선택 상태를 파랑 배경 대신 **중립 반전**(배경 `--ink`, 글자 `--panel`, 대비 14.21)으로 그려 파랑을 가격 전용으로 비우는 것을 함께 권합니다.
설정 위치: 머리의 테마 ◐ 옆 '더보기' 안 "색 규칙" 한 항목, 저장 키 `qse-color-rule`.

## 3. 글자

- 글꼴: 지금의 시스템 글꼴 스택 유지(-apple-system, Apple SD Gothic Neo, Noto Sans KR). 웹 글꼴은 쓰지 않습니다(같은 Wi-Fi 폰, 외부 의존 없음).
- 숫자: 숫자가 있는 모든 셀·타일에 `font-variant-numeric: tabular-nums`(지금은 `.num`에만, style.css:31).
- 크기 7단계: 11(배지·축) / 12(meta) / 13(표 본문) / 14(본문) / 16(패널 제목, 현재 15) / 20(화면 제목 h1, 현재 없음) / 28(카드 점수, 현재 34).
- 굵기 3단계: 400 / 600 / 700.
- 줄 간격: 본문 1.5, 표 1.35, 쉬운 설명 상자 1.7(지금 유지).
- 한국어 라벨: `word-break: keep-all`(세그먼트 "오늘 순/위" 해결).

## 4. 간격·모서리·폭

- 간격 4 px 격자: 4 / 8 / 12 / 16 / 24 / 32. 패널 안 여백 16(현재 14), 패널 사이 16.
- 모서리: 4(배지·입력) / 6(버튼) / 8(패널) / pill(판단 알약).
- 내용 폭: 글 위주 화면 1,280 px 유지. 표 화면(순위·스크리너·시장 개요·차트분석·위원회 표)은 1,680 px. 1,600 px 이상에서 순위 화면은 **두 열**: 왼쪽 순위 표, 오른쪽 고른 종목의 요약 띠(카드는 그 자리에서 열지 않고 오른쪽에).
- breakpoint 4단계: 폰 ≤ 640 / 태블릿 641–1023 / 데스크톱 1024–1599 / 넓은 화면 ≥ 1600. JS는 같은 값을 `matchMedia` 한 곳에서.

## 5. 부품 체계

DESIGN_SYSTEM_ASSESSMENT.md 6절의 `ui.js` 목록을 따릅니다. 이 방향에서 새로 필요한 부품 세 가지:

1. **상태 띠 `ui.statusStrip`** — 점수 탭·점수 상세·오늘 탭 맨 위 한 줄, 높이 36 px:
   `시장 상태 15/100 나쁨 · 새 주문 크기 50% · 성향 기본 · 점수 검증: 아직 근거 없음 ▸`
   ▸를 누르면 한 곳에서만 전체 설명을 펼칩니다. 지금의 노란 경고 문구는 이 띠 안에서 같은 글자 크기로 남습니다(없애지 않음).
2. **점수 칩 `ui.scoreChip`** — 표용: 정수 점수 + 판단 알약 + 자료 충족 점 3단계. 경계 ±1점 안이면 "경계 근처" 작은 표식(표식 폭은 소유자 결정, 구간 경계는 그대로).
3. **규칙 엔진 카드 머리** — 각 카드 이름 옆 고정 배지 "규칙 엔진". 카드 묶음은 점수 카드보다 한 단계 낮은 시각 무게(배경 `--bg`, 제목 14 px). 섹션 제목 줄에 "실존 투자자의 의견이 아닙니다"를 올림.

안내 상자는 세 모양으로 나눕니다: **gate**(실행을 막음 — 왼쪽 굵은 `--warn` 띠 + 굵은 제목), **risk**(종목별 위험, 예: 합병 묶임 — 행 안 두 번째 줄 문장, 툴팁 아님), **info**(참고 — 색 없는 작은 칩, 예: 자사주 취득).

## 6. 표

- 행 높이: 데스크톱 32 px, 터치 44 px. 숫자 오른쪽 정렬, 점수는 정수.
- 머리 행 sticky(`top`은 sticky 머리글 높이만큼).
- 열 우선순위(순위 표): 순위 · 종목 · 점수 칩 · 판단 · 진입 · 영역 4개 · 점수 변화 · 업종 · 가점/감점.
- 태블릿(641–1023): 영역 4개를 하나의 작은 묶음 막대로 줄이고 판단을 종목 바로 옆으로.
- 폰(≤ 640): 행을 두 줄 카드로 — 1줄 "순위 · 이름 · 점수 칩", 2줄 "판단 · 진입". 영역·업종·가점/감점은 행을 누르면. **판단·진입을 숨기지 않음**(지금은 숨김, style.css:438).
- 열 전체가 비면 접고 한 줄 안내(D3).
- 한국 종목: 이름 굵게 앞, 코드 흐리게 뒤.

## 7. 차트

- 그리기 전 막대 검사: open ≤ 0 또는 [low, high] 밖이면 몸통 없이 고저선 + 툴팁 "시가 없음"(D1).
- 마지막 미확정 봉은 속 빈 몸통.
- 축 눈금: 1·2·2.5·5×10ⁿ 반올림 간격, 천 단위 구분, 시장별 소수 자리. 두 가격 차트가 같은 함수.
- 축 글자 11 px `--muted`, 격자 `--grid`.
- 스파크라인: 시작값 점선 기준선, 카드 안 "30일 범위 ±x %".
- 캔버스: `role="img"` + 한 문장 요약(기간, 시작·끝 값, 등락). 스파크라인은 `aria-hidden`.
- FC-1은 지금 형태 유지, 중간 눈금과 배지 문구만.

## 8. 이동

- **데스크톱**: 머리 한 줄(브랜드 · 시장 · 검색 · ⌘K · '더보기' 메뉴[지금 수집, 폰 연결, 테마, 색 규칙]) + 묶음 탭 줄 sticky 40 px + 하위 탭. `내 계좌` 버튼은 묶음 탭과 겹치므로 '더보기'로.
- **폰**: 머리 48 px 한 줄(브랜드 · 시장 · 검색 아이콘). 화면 아래 탭 막대 56 px + safe-area: 오늘 · 시장 · 종목 · 점수 · 더보기(차트, 내 계좌, 검증·기록). 맨 위로 버튼.
- **클릭 규칙 하나**: 종목 코드·이름 → 종목 화면, 점수 숫자·판단 배지 → 점수 카드. 명령창에 "X 점수".
- 해시에 보기 이름까지(`#qsf/rank`, `#qsf/AAPL`), 스타일(스윙/장기) 기억.
- 하위 탭 이름 정리(UX_WORKFLOW_ASSESSMENT.md 4절).

## 9. 화면 위계

**오늘 탭** (위에서 아래로)
1. 상태 띠(시장 상태 + 검증 상태)
2. 헤드라인 문장 — 시장 상태가 '나쁨'이면 그 사실과 "새 주문 크기 절반 규칙 적용 중"을 함께(등급 분류는 그대로)
3. 숫자 타일 — 모든 등락에 "1일"·"1개월" 꼬리표
4. 오늘의 후보 — 제목 바로 아래 "점수가 높다고 수익이 더 좋았다는 근거는 아직 확인되지 않았습니다"(지금 페이지 맨 끝에 있는 같은 문장을 옮김)
5. 할 일 — 한 줄 제목 + 숫자 하나, 본문은 펼침. 수준별 왼쪽 띠 색

## 10. 상호작용

- hover 툴팁이 위험·정의 문장의 **유일한** 자리가 되지 않게: 툴팁 문장은 화면 안 문장이나 펼침으로도 볼 수 있어야 함(폰).
- 접기는 모두 `<details>/<summary>`.
- 선택 상태는 `aria-pressed`/`aria-current`, 전역 `:focus-visible` 2 px `--accent` 윤곽.
- 브라우저 `alert`는 화면 안 메시지로, 되돌릴 수 없는 동작만 확인 대화상자.
- 오늘 탭은 돌아올 때 그려 둔 화면을 먼저 보여 주고 뒤에서 갱신.

## 11. 어두운/밝은 테마

- 기본은 어두운 테마(사용자가 씀). 밝은 테마도 유지하고 대비를 고침(`--up` #067a4b, `--warn` #8f5600).
- 팔레트 정의는 한 벌: 첫 페인트 전 `<head>`의 작은 스크립트가 `data-theme`을 정하고, CSS는 `[data-theme="dark"]` 한 곳만. 테스트(test_chart_analysis.py:180)를 같이 고침.
- 색 규칙(국제식/한국식/시장 따라)은 테마와 따로 저장.

## 12. 하지 않을 것

- 프레임워크 이전, 빌드 단계, CDN·웹 글꼴 의존.
- 점수·공식·구간 경계·진입/청산·포트폴리오 규칙 변경.
- P6-11B와 QSF 점수의 결합.
- 규칙 엔진을 실제 투자자의 의견처럼 보이게 하는 표현(사진, 서명, 1인칭 문장).
- 경고·출처 문장의 삭제. 줄이는 것은 반복의 **길이**이지 문장 자체가 아님.
