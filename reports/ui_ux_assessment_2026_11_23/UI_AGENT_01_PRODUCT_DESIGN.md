# UI Agent 01 — 제품 디자인 평가 (금융 플랫폼 관점)

작성: 2026-11-23 · 역할: 시니어 프로덕트 디자이너(금융 플랫폼) · 읽기 전용 평가

## 요약
- 어두운 테마의 색 token, 패널·카드·배지 구성은 한 체계로 묶여 있고, 차트분석(10)·시장 개요(03)·순위 표(18)는 "연구 도구"로 보일 만한 수준입니다.
- 가장 큰 약점은 위계입니다. 점수 상세는 6,750 px·13,194자·meta 260줄의 긴 글이고, 점수 탭은 네 보기 위에 같은 머리 블록(약 270 px)과 시장 상태 문단을 되풀이합니다.
- 신뢰를 직접 깎는 표시 문제가 있습니다: 오늘 탭 지수 타일의 "1개월" 표기가 당일 등락 옆에 붙어 읽힘(app.js:374), 한국 종목 시가 0 봉(D1), 배당수익률 10.05%(D2), 동종업계 표 7개 열 전부 "—"(D3).
- 입력창 두 개(#qsfticker, #cha-q)는 스타일이 없어 브라우저 기본 회색으로 보이고, 글자 크기가 12종 이상·인라인 style 731개라 화면마다 결이 조금씩 다릅니다.
- 제안 점수: Visual design 12/20, Information architecture 10/20.

## 평가 범위와 근거
- 범위: 시각 위계, 배치, 정보 밀도, 간격, 글꼴, 색, 일관성, 전문가용 외관, 투자 제품으로서의 신뢰, 첫인상.
- 근거: 증거 묶음(EVIDENCE.md)의 측정표·결함 D1–D8, 스크린샷 01, 02, 03, 06, 07, 10, 17, 18, 19, 21, 22, 23, 24, 25, 26, 28, 29, 30, 31, 32, 36, 38, 39, 40을 직접 봄. 소스는 `~/Developer/quant-stock-engine/terminal/static/style.css`, `app.js`, `qsf.js`, `chart.js`를 일부 확인.
- 스크린샷은 800 px 폭 축소본이라 작은 글자·1 px 선의 정확한 색은 판단하지 않았습니다.
- 비교 대상(Bloomberg Terminal, Koyfin, FactSet, TradingView)은 일반적으로 알려진 화면 구성만을 말로 비교했고, 실제 제품을 열어 보지 않았습니다.

## 강점
1. **색 token 체계가 있음.** style.css 1–29행에 ink/muted/up/down/accent/warn과 계열색 --s1..--s8, 이동평균색 --ma5..--ma200이 정의되어 있고 어두운 테마는 모든 글자색이 WCAG 4.5:1을 넘습니다(증거: 어두운 테마 대비 ink 14.21 … warn 8.35). 지금 사용자가 쓰는 테마가 바로 이 어두운 테마입니다.
2. **차트분석 화면(10, 11)이 가장 전문가 도구답습니다.** 캔들, 볼린저밴드, 이동평균 토글, 신호 표시, 거래량, RSI, MACD가 한 열로 정렬되어 TradingView의 기본 배치와 비슷한 읽기 순서를 줍니다.
3. **시장 개요(03)의 작은 카드 묶음**(지수 / 금리·환율·원자재 / 섹터 ETF)은 Koyfin의 시장 대시보드와 같은 small multiples 방식이며 카드 크기·간격이 일정합니다.
4. **출처와 시각이 거의 모든 패널에 붙어 있습니다.** 예: 01 "출처: Yahoo Finance (일봉 종가, 지연) · 받아온 시각", 06 "출처: Yahoo Finance quote summary · 받아온 시각 … 실데이터". 무료 지연 데이터 도구로서 정직한 표시이며, 상용 도구보다 오히려 명시적입니다.
5. **검증 상태를 숨기지 않습니다.** 점수 탭 맨 위 경고(17 "점수가 높다고 수익이 더 좋았다는 근거는 아직 확인되지 않았습니다"), 신뢰도(자료의 양) 표기(22), 판정 일정 0/30(21). 투자 제품의 신뢰는 이런 표시에서 나옵니다.
6. **순위 표(18)는 훑어보기 좋습니다.** 영역별 미니 막대 + 숫자, 판단 칩(매수 후보/관찰), 가점·감점 두 줄이 한 행에 들어가 50행을 세로로 빠르게 비교할 수 있습니다.
7. **점수 카드의 '점수를 올린 요인 / 깎은 요인' 상자(22)**는 점수의 근거를 두 열로 대칭 배치해 좋은 설명 장치가 됐습니다.
8. **어느 폭에서도 페이지 가로 넘침이 없습니다**(증거: 1920/1280/768/390 모두 overflow-x 없음).

## 문제

### UI-01 점수 상세가 '보고서 한 편'처럼 길고 위계가 평평함
- 근거: 측정표 "score detail AAPL" 행 — h 6,750 px, 13,194자, 표 16, details 22, meta 260줄, 인라인 style 731개. 스크린샷 22·23·24: 시장 상태 문단 → 두 점수 카드 → 영역별 점수 → 진입 → 보유 계획 표 → 판단이 바뀌는 조건 → 다섯 투자자 카드 → 통합 위원회 → P6-11B 한 줄 → FC-1 범위 막대가 같은 굵기의 글로 이어짐.
- 영향: 사용자가 "이 종목, 지금 무엇이 핵심인가"를 한눈에 못 봅니다. FactSet의 종목 tearsheet나 Koyfin의 종목 요약은 맨 위 한 줄 띠(가격·핵심 지표·등급)와 그 아래 탭으로 깊이를 나눕니다. 여기서는 모든 층이 한 스크롤에 펼쳐져 있습니다.
- 심각도: P1 · 확신도: 높음
- 권고: 카드 맨 위에 고정 요약 띠(점수, 구간, 신뢰도, 진입 상태, 손절·목표 기준선)를 두고, 아래를 '근거 / 계획 / 다섯 규칙 엔진·위원회 / 가격 범위' 정도의 내부 탭이나 접힘으로 나눕니다. 내용·판정 로직은 그대로 두고 배치만 바꾸는 제안입니다.

### UI-02 점수 탭의 머리 블록과 시장 상태 문단이 반복됨
- 근거: D6(약 270 px 머리 블록이 네 보기 위에 모두 있음, 17·19·21에서 동일), D8(시장 상태 블록이 순위·주문 계획·종목 상세에 각각 전문으로 나옴, 17·22). 17에서 1440 폭 첫 화면에 순위 표는 3행만 보입니다.
- 영향: 핵심 표가 첫 화면 아래로 밀리고, 같은 문단을 매번 다시 읽게 되어 "프로토타입" 인상을 줍니다. Bloomberg는 상태를 한 줄 상단 띠로 고정하고 본문은 바로 데이터로 시작합니다.
- 심각도: P1 · 확신도: 높음
- 권고: 경고·성향 스위치·시장 상태를 한 줄 상태 띠(예: "시장 상태 15/100 나쁨 · 새 주문 크기 50% · 성향 기본 · 검증 미확인 ▸")로 줄이고, 설명 문단은 띠를 눌렀을 때 한 곳에서만 펼칩니다. 경고 문구 자체는 없애지 않습니다.

### UI-03 오늘 탭 지수 타일의 등락 표기가 오독됨
- 근거: app.js:374 `${pct(i.change_pct)} <span class="meta">1개월 ${pct(i.change_1m_pct, 1)}</span>` — 당일 등락에는 기간 표기가 없고, 1440 폭(01, 28, 03)에서는 줄바꿈 때문에 "−3.70% 1개월" / "−9.8%"로 보여 당일 수치가 1개월 수치처럼 읽힙니다. 390 폭(38)에서는 "−3.70% 1개월 −9.8%"로 한 줄이라 의도대로 읽힙니다.
- 영향: 첫 화면 첫 숫자의 의미가 틀리게 읽힐 수 있습니다. 금융 화면에서 가장 비싼 종류의 오해입니다.
- 심각도: P1 · 확신도: 높음
- 권고: 두 수치에 모두 기간 꼬리표("1일", "1개월")를 붙이고, 같은 줄에 나란히 두거나 두 줄로 고정합니다. 덧붙여 VIX는 오를 때 초록(03, 01 "+26.20%")으로 칠해지는데, 위험 지표의 상승을 '좋음' 색으로 보이게 하므로 VIX 같은 지표는 중립색을 검토할 만합니다(P3).

### UI-04 눈에 보이는 잘못된 숫자가 신뢰를 직접 깎음
- 근거: D1 — 31에서 한국 종목 장중 시가 0.0 봉이 바닥에서 올라오는 긴 초록 막대로 그려지고 y축이 0 근처까지 늘어 1년 가격이 위로 눌림. y축 숫자는 천 단위 구분이 없음(app.js:499 `v.toFixed(v >= 100 ? 0 : 2)`). D2 — 배당수익률 10.05%(31), app.js:435가 Yahoo 값을 그대로 %로 붙임(단위 미확인). D3 — 07 동종업계 표 12개 열 중 PER·PBR·FCF 수익률·영업이익률·ROE·3년 매출성장·부채/자본 7개 열이 87행 모두 "—". 31의 시가총액 "₩1124.61조"도 천 단위 구분이 없음.
- 영향: 사용자는 한 번 틀린 숫자를 본 뒤 나머지 숫자도 의심합니다. 전부 비어 있는 열은 "아직 완성 안 된 화면"으로 보입니다.
- 심각도: D1 P1(확신도 높음), D2 P1(확신도 보통: 단위 미확인), D3 P2(확신도 높음), 축·시가총액 구분자 P3(확신도 높음)
- 권고: 시가 0 같은 불가능한 봉은 그리지 않거나 '자료 이상' 표식으로 대체, 축 숫자에 천 단위 구분, 전부 비어 있는 열은 숨기고 "다음 스캔 후 채워짐" 한 줄로 대신합니다.

### UI-05 스타일이 빠진 입력창 두 개
- 근거: #qsfticker(qsf.js:164)와 #cha-q(chart.js:44)는 style.css:151–152, 244에서 크기만 정하고 배경·테두리·글자색이 없음. 17·19·21·39에서 점수 탭 종목 입력이 넓은 밝은 회색 막대, 10에서 차트 입력이 회색 상자로 보임. 상단 검색창(style.css:37)·.form input(style.css:132)은 어두운 배경 + 1 px 선.
- 영향: 가장 자주 쓰는 입력이 다른 입력과 달라 "급히 붙인 화면" 느낌을 줍니다.
- 심각도: P2 · 확신도: 높음
- 권고: 입력창 공통 규칙 하나(배경 --bg, 테두리 --line, radius 6 px, 높이 통일)를 두고 모든 input/select가 따르게 합니다.

### UI-06 글자 크기·모서리·인라인 style이 체계 밖에서 늘어남
- 근거: 화면에서 본 글자 크기 10.8, 11, 11.7, 12, 12.5, 13, 14, 15, 16, 18, 20, 28, 34 px(측정표). style.css의 font-size 선언 12종, border-radius 8종(2–14 px). 인라인 style 출현 qsf.js 52, portfolio.js 34, committee.js 29. 패널 제목 h2는 15 px(style.css:72)로 본문 14 px와 1 px 차이라 제목이 제목처럼 보이지 않음(17, 21의 섹션 제목). 문서에 h1 없음.
- 영향: 같은 종류의 정보(표 머리, 보조 설명, 배지)가 화면마다 미세하게 다른 크기로 나와 정돈되지 않은 인상을 줍니다. 위계 단계가 너무 촘촘해 오히려 위계가 안 보입니다.
- 심각도: P2 · 확신도: 높음
- 권고: 글자 크기 5단계(11·12·14·16·24 등) token, radius 3단계(4·6·8)로 정하고 인라인 style을 class로 옮깁니다. 화면 제목은 h1 한 개, 패널 제목은 본문보다 2단계 크게.

### UI-07 내부 식별자가 사용자 화면 앞면에 노출됨
- 근거: 22 "스윙 · US_SWING_V2", "QSF-1.5.2"; 26 "P6-11B (MODEL_RANK_E)", 실행 ID "20261120T221310Z_market_scan_0570e1", "20261120T222252Z_bb6bf0"; 21 바닥글 "TERMINAL-4.0"; 17·19 "QSF-1.4.1 공식으로 기록된 스캔 … QSF-1.5.2" 안내.
- 영향: 감사 추적에는 필요하지만 본문 글자와 같은 무게로 놓여 화면이 개발 도구처럼 보입니다. 상용 도구는 이런 정보를 툴팁이나 '정보' 패널에 둡니다.
- 심각도: P2 · 확신도: 보통
- 권고: 식별자는 지우지 말고 작은 '기술 정보' 접힘이나 마우스 툴팁으로 옮깁니다. P6-11B 화면은 지금처럼 별도 화면·별도 표기를 유지합니다.

### UI-08 1920 폭에서 3분의 1이 빈 공간
- 근거: D5, 32·33 — main max-width 1280 px(style.css:68), 패널 1,248 px, 약 640 px 미사용.
- 영향: "밀도 높은 작업용 화면"이라는 terminal 이름과 어긋납니다. Bloomberg·Koyfin은 넓은 화면에서 여러 패널을 나란히 놓습니다. 반대로 긴 설명 글은 지금 폭이 읽기 좋으므로 전부 넓힐 일은 아닙니다.
- 심각도: P2 · 확신도: 높음
- 권고: 표·차트 중심 화면(순위, 스크리너, 시장 개요, 차트분석)만 1600 px 이상에서 폭을 넓히거나 두 열(예: 순위 표 + 선택 종목 요약)로 나눕니다. 글 위주 화면은 지금 폭 유지.

### UI-09 휴대폰에서 첫 화면 대부분이 머리글이고 순위가 너무 아래에 있음
- 근거: 38·39 — 머리글 약 415 px(브랜드, 시장 전환, 버튼 4개, 검색, 그룹 탭 두 줄). D4 — 점수 탭이 마지막에 연 AAPL 카드를 순위 위에 두어 순위 표가 y ≈ 8,790 px에서 시작, 가로로 밀리는 표 13개. 39에서 보기 전환 버튼 글자가 "오늘 순 / 위", "스크리 / 너"로 끊김.
- 영향: 사용자는 다른 기기에서 쓰는 계획이 있어 휴대폰 화면이 중요합니다. 지금은 확인용으로도 불편합니다.
- 심각도: P1 · 확신도: 높음
- 권고: 휴대폰 폭에서 버튼 4개를 메뉴 하나로 접고 그룹 탭은 가로 스크롤 한 줄로. 점수 탭은 순위를 먼저, 열어 둔 종목 카드는 아래 또는 별도 화면으로. 세그먼트 버튼은 줄바꿈 금지 + 가로 스크롤.

### UI-10 태블릿 폭에서 순위 표의 판단 열이 화면 밖
- 근거: 36(768 폭) — 판단 칩이 "매수 후"에서 잘리고 진입·가점/감점 열은 보이지 않음. 측정표: 768 폭 점수 페이지 가로 스크롤 표 2개. 휴대폰 전환점이 760 px(style.css:437)이라 768은 데스크톱 배치를 그대로 받음.
- 영향: 이 표에서 가장 중요한 열(판단)이 가려집니다.
- 심각도: P2 · 확신도: 높음
- 권고: 좁은 폭에서는 영역별 네 막대를 하나의 작은 묶음으로 줄이고 판단 열을 종목 바로 옆으로 당깁니다.

### UI-11 한국 화면의 표기 관례와 행 소음
- 근거: 30 — 행마다 6자리 코드가 굵게 앞서고 한글 종목명은 작고 흐리게 뒤따름; 상위 15행 중 다수에 "자사주 취득 · 참고" 배지. 31 — 한국 종목 하락(−5.68%)이 빨강. 소스에서 한국 시장용 색 관례 전환을 찾지 못함(style.css, app.js 검색).
- 영향: 한국 사용자는 이름으로 종목을 알아봅니다. 같은 배지가 여러 행에 반복되면 배지의 신호 가치가 떨어집니다. 사용자의 증권사(토스증권)를 포함한 국내 화면은 보통 상승 빨강·하락 파랑이라, 같은 빨강이 반대 뜻으로 쓰여 혼동될 수 있습니다.
- 심각도: P2 · 확신도: 보통(색 관례는 사용자 선택 사항)
- 권고: 한국 시장에서는 종목명을 앞·굵게, 코드는 뒤·흐리게. '참고' 등급 배지는 아이콘 하나 + 툴팁으로 줄이기. 상승/하락 색 관례는 설정 하나로 사용자에게 묻는 것을 권합니다(디자인 결정, 규칙 변경 아님).

### UI-12 오늘 탭 아래쪽 '할 일과 알림'이 같은 무게의 글 카드 더미
- 근거: 02 — "참고 8" 아래 카드마다 2–4줄 문단 + "… 탭에서 보기" 버튼이 같은 크기·같은 테두리로 반복. 측정표 today: 3,194자, meta 28줄, 높이 2,043 px.
- 영향: 상단 헤드라인("먼저 볼 것은 없습니다. 오늘 챙길 것이 1건 있습니다.")은 좋은 장치인데, 그 아래는 우선순위가 시각적으로 구분되지 않습니다.
- 심각도: P2 · 확신도: 높음
- 권고: 항목마다 한 줄 제목 + 숫자 하나만 보이고 본문은 펼침으로. '오늘 챙길 것'과 '참고'의 카드 모양(왼쪽 색 띠, 크기)을 다르게.

### UI-13 다섯 규칙 엔진 카드에 '규칙 번역' 표지가 카드 단위로 없음
- 근거: 23 — 버핏식·멍거식·그레이엄식·린치식 카드가 점수 카드와 같은 무게의 테두리 카드로 나란히 놓임. 패널 부제 "알려진 원칙을 규칙으로 옮긴 참고"와 24 하단 "실존 투자자의 실제 의견이 아닙니다"는 있지만, 개별 카드에는 그런 표지가 없음.
- 영향: 카드 하나만 캡처하거나 훑어볼 때 실제 인물의 의견처럼 읽힐 위험이 있습니다. 금융 제품에서 출처 오인은 신뢰 문제입니다.
- 심각도: P2 · 확신도: 보통
- 권고: 각 카드 이름 옆에 작은 고정 배지("규칙 엔진")를 두고, 이 묶음을 점수 카드보다 한 단계 낮은 시각 무게(더 옅은 배경, 작은 제목)로 둡니다.

### UI-14 숫자 표기 형식이 섞여 있음
- 근거: 22·40 — 유동성 근거에 11자리 원시 숫자 + "달러"; 06·07 — "$4.98조", "$5.07조"; 31 — "₩1124.61조"; 차트 축 "185000" 형태(D1). 같은 크기 개념이 화면마다 다른 단위·구분자로 나옴.
- 영향: 비교가 느려지고 정돈되지 않은 인상을 줍니다. 상용 도구는 큰 수를 한 규칙(예: 1.72조 / 17.2B)으로 통일합니다.
- 심각도: P3 · 확신도: 높음
- 권고: 큰 수 서식 함수 하나로 통일(통화 기호 위치, 천 단위 구분, 조/억 단위)하고 설명 문장에서도 같은 함수를 씁니다.

### UI-15 밝은 테마의 상승·주의 색 대비 부족
- 근거: 증거 대비표 — 밝은 테마 up #0a8f5a 4.13, warn #b26b00 4.20(4.5 미만). 28·29에서 작은 초록 등락 숫자와 주황 배지가 흐리게 보임.
- 영향: 사용자는 현재 어두운 테마를 쓰지만, 밝은 테마로 바꾸는 순간 핵심 색 숫자가 덜 읽힙니다.
- 심각도: P2 · 확신도: 높음
- 권고: 밝은 테마 up·warn token만 한 단계 어둡게 조정.

## 전문 플랫폼과의 구체적 차이 (말로만 비교)
- **Bloomberg Terminal**: 한 줄 상태 띠 + 기능 코드 + 넓은 화면 다중 패널. 이 앱은 ⌘K 명령 팔레트가 있어 방향은 맞지만, 넓은 화면을 쓰지 않고(UI-08) 상태 정보를 문단으로 반복함(UI-02).
- **Koyfin**: 종목 화면 상단 요약 띠, 사용자가 고르는 열 구성, 통일된 숫자 서식. 이 앱은 열 고정, 숫자 서식 혼재(UI-14), 빈 열 노출(UI-04).
- **FactSet**: 한 장짜리 종목 tearsheet. 이 앱의 점수 상세는 같은 역할을 하려 하나 6,750 px 길이의 글(UI-01).
- **TradingView**: 차트가 화면의 주인공이고 축·봉 품질이 일정. 이 앱의 차트분석은 근접하지만 불가능한 봉(시가 0)을 걸러내지 않고 축 숫자 서식이 없음(UI-04).
- 이 앱이 상용 도구보다 나은 점: 검증 미확인·신뢰도·자료 출처를 화면에 정직하게 드러내는 점(강점 4·5). 이것은 디자인 정리 과정에서 약해지지 않아야 합니다.

## 점수 제안

**Visual design: 12 / 20**
색 token, 어두운 테마 대비, 패널·카드·배지·세그먼트 버튼의 기본 부품은 한 체계로 일관되고, 시장 개요·차트분석·순위 표는 연구 도구로 보기에 손색없는 외관입니다. 그러나 글자 크기 12종 이상·radius 8종·인라인 style 수백 개로 미세한 불일치가 화면마다 쌓이고(UI-06), 스타일이 빠진 입력창(UI-05), 내부 식별자 노출(UI-07), 섞인 숫자 서식(UI-14), 그리고 시가 0 봉·10% 배당·빈 열 같은 눈에 띄는 잘못된 숫자(UI-04)가 "잘 만든 개인 프로토타입"과 "전문 연구 플랫폼" 사이의 간격을 만듭니다. 밝은 테마 대비 미달(UI-15)도 감점 요인입니다.

**Information architecture: 10 / 20**
7개 그룹 탭 + 17개 하위 탭이라는 큰 틀은 이해할 만하고, '오늘' 탭의 헤드라인이 첫 질문에 답하는 구조도 좋습니다. 하지만 가장 중요한 화면인 점수 탭에서 같은 머리 블록과 시장 상태 문단이 반복되고(UI-02), 종목 상세는 모든 층이 한 스크롤에 평평하게 펼쳐져 요약→근거→세부의 단계가 없으며(UI-01), 마지막 연 종목 카드가 순위보다 앞에 오는 등 화면 순서가 상황에 따라 흔들립니다(D4, UI-09). 오늘 탭 아래쪽도 우선순위가 시각적으로 나뉘지 않습니다(UI-12). 정보는 충분하나 "어디부터 볼지"를 화면이 정해 주지 못해 절반 정도의 점수로 봅니다.

## 확인하지 못한 것
- 실제 화면을 직접 조작하지 않았으므로 hover, 툴팁, 접힘을 연 뒤의 배치, 애니메이션, 첫 그리기 체감 속도는 확인하지 못함.
- 스크린샷이 800 px 축소본이라 1 px 선 색, 11 px 이하 글자의 실제 선명도는 확인하지 못함.
- 코인 그룹 화면, 맵(04)·거시(05)·계좌(13–16)·비교(12)·연구실(27) 화면은 이번 범위에서 자세히 보지 않았음(측정표만 참고).
- D2 배당수익률 값의 원래 단위, D7 날짜 기본값의 원인은 확인하지 못함.
- 비교 대상 상용 제품은 이번에 열어 보지 않았고, 일반적으로 알려진 구성만으로 비교함.
