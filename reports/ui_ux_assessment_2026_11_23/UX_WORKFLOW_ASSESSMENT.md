# UX 작업 흐름 평가 (2026-11-23)

작성: 총괄 디자인 평가자. 주 근거는 Agent 3(W1~W16)의 일곱 작업 추적이며, Agent 5(R1~R8)·Agent 6(레드팀 #1·#4)·조정자 측정을 더했습니다.

**측정 방법의 한계**: 클릭 수는 코드의 이벤트 처리기를 따라 센 값이고, 스크롤 거리는 측정표의 페이지 높이와 스크린샷 속 위치로 어림한 값입니다. 앱을 직접 눌러 보지는 않았습니다. 1440 화면은 1440×900, 390 화면은 390×844 뷰포트입니다.

## 요약

- 매일 하는 두 작업 — **아침 확인**과 **점수 이유 보기** — 은 0~3클릭으로 끝나고 설명 순서가 좋습니다.
- **"들어가도 되나·얼마나·손절은"**(작업 4)과 **"모델이 통하나"**(작업 6)는 정보가 2개 묶음, 3~4개 화면에 흩어져 있고 서로 가는 링크가 없습니다.
- **휴대폰**(작업 7)에서는 순위가 지난번 카드 밑 약 8,790 px에 묻히고, 판단·진입 열이 숨겨집니다.
- 점수: **8 / 15** (Agent 3 제안에 동의).

## 2. 작업별 핵심 관찰

### 작업 1 — 아침 확인
- 잘 됨: 해시가 없으면 '오늘'이 열리고(app.js:739), 헤드라인 문장 → 타일 6개 → 후보 표 → 수준별 할 일 순서(01, 02).
- 문제: 첫 문장은 등급 이름을 그대로 문장으로 씁니다(terminal/assistant.py:16, 326). "먼저 볼 것"(ACT)은 손실 관련 항목만이라, 계좌 기록이 없으면 시장 상태 15/100인 날에도 늘 "없습니다"입니다. "새 주문 크기 50 %"는 아래 카드 한 장에만 있습니다(02). 사용자가 토스 앱에서 손으로 넣는 주문에는 이 규칙이 적용되지 않으므로, 첫 문장이 말하지 않으면 규칙의 뜻이 약해집니다(레드팀 #1). **등급 분류는 그대로 두고 문장 조립만** 바꾸는 제안입니다(P1-3).

### 작업 4 — 진입에서 주문까지
- 지금 길: 카드 '진입' → '보유 계획(가설)' 펼치기 → 위로 스크롤(약 270 px 머리 블록 아래) → '주문 계획·모의 장부' → 14열 표에서 눈으로 찾기. 또는 내 계좌 → 매매 보조 → 크기 계산기에 코드 입력.
- 제안 길: 카드의 진입 부분에 "이 종목 주문 계획 줄 보기"와 "크기 계산기에 넣기" 링크 두 개, 빈 주문 계획에 "내 계좌에서 기록하기" 버튼(P1-13). 계산·한도는 그대로.

### 작업 7 — 휴대폰
- 머리 영역 약 415 px(브랜드·시장 전환·버튼 4개·검색 3줄 + 묶음 탭 2줄, 38). 600 px 이하에서는 머리가 고정되지 않아(style.css:385) 다른 묶음으로 가려면 맨 위까지 올라가야 합니다.
- 점수 탭: 머리 블록 다음 보기 전환이 약 700 px 지점, 버튼 글자가 "오늘 순/위"로 꺾임(39). AAPL 상세가 남아 있으면 순위 표는 y≈8,790 px(D4), 상세 카드는 시장 상태 블록만으로 첫 화면 절반(40).
- 760 px 아래에서 `.w`, `.w2` 열이 숨겨져 업종·전일 대비·영역 4개·**판단·진입**이 빠지고 순위·종목·점수·가점/감점만 남음(qsf.js:446-450, style.css:438). Agent 5는 이 점을 다루지 않아 반응형 점수를 0.5 낮췄습니다.
- 툴팁 전용 설명(신뢰도의 뜻, 합병 위험)은 폰에서 보이지 않습니다. 터치용 `#taptip` 설명 막대가 있으나 길게 눌렀을 때 실제 동작은 **확인하지 못함**.

## 3. 이동 구조

- **3단 + 전환 3개**: 묶음 7개 → 하위 탭 17개 → (점수 탭) 보기 4개. 여기에 시장(미국/한국/코인), 스타일(스윙/장기), 성향(방어적/기본/공격적)이 겹칩니다.
- **같은 동작, 다른 결과(W5)**: 종목 코드를 누르면 — 오늘 후보 칩·명령창은 종목 화면, 순위 줄은 그 자리 카드, 스크리너·변화 목록은 보기를 바꾸고 순위 맨 위 카드(qsf.js:548, 627). 스크리너에서 누르면 스크리너를 떠납니다. 제안 규칙: **종목 코드·이름 = 종목 화면, 점수 숫자·판단 배지 = 점수 카드**, 명령창에 "X 점수" 항목(P2-15).
- **고정되지 않는 이동 줄(W12)**: 묶음 탭 줄은 어느 폭에서도 sticky가 아님(style.css:58). 최대 11,926 px 페이지에서 이동할 때마다 끝까지 스크롤.
- **'… 탭에서 보기'(W13)**: 탭만 열고 가리키는 보기·종목으로 가지 않음(assistant.js:7-10).
- **상태 기억(W9)**: 보기·접힘은 localStorage, 스타일(스윙/장기)은 기억 안 함, 해시는 탭과 카드만. 장기를 보는 날에는 새로고침마다 다시 고름. 뒤로 가기로 이전 보기에 못 돌아감.

## 6. 정보를 펼치는 방식

- 상세 페이지 하나에 details 22개, 13,194자, meta 260줄. 접힌 순서는 질문 순서와 맞지만, 펼치지 않아도 보이는 글이 이미 많음(시장 상태 5줄, 공시 설명, 위험 설명, 공식 버전 안내). '먼저 읽을 것'과 '참고'가 같은 회색 글씨.
- 카드의 경고(notice) 종류 — 오래된 자료, 위험 게이트, 실적일 미상, 합병, 시세 점검 — 가 모두 같은 노란 상자(qsf.js:354-358). 실행을 막는 것(게이트)과 참고를 모양으로 구분해야 함(ui.notice tone, P2-4).
- 좋은 예: 추적·검증 보기는 판정 일정만 펼쳐 두고 상태를 기억(qsf.js:141-154). 실패와 '없음'을 구분하는 오류 문장(qsf.js:462, assistant.js:101).

## 7. 강점 (지킬 것)

- 첫 화면이 결론부터 말함(헤드라인 + ACT/DUE/INFO).
- 카드가 "왜"에 바로 답함(요약 → 올린/깎은 요인 → 검산).
- 순위 줄 제자리 펼침, 돌아오면 스크롤·펼침 복원.
- 명령창(탭 별칭, 최근 종목, 문장 질문), 종목 주소 해시.
- 빈 상태 대부분이 다음 행동을 알려 줌(13, 14, 20), 가상 장부의 '가상의 금액' 배지.

## 8. 점수 근거 (8 / 15)
