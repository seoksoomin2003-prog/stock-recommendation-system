- 아침 확인(작업 1)과 점수 이유 보기(작업 3)는 잘 됩니다. 첫 화면 '오늘'이 한 문장 헤드라인, 숫자 타일, 진입 가능한 후보, 수준별 할 일(먼저 볼 것 / 챙길 것 / 참고)을 클릭 없이 보여 줍니다. 순위 표는 줄 하나를 누르면(1번) 그 자리에서 카드가 펼쳐지고, 카드는 요약 한 문장, 점수를 올린 요인·깎은 요인, 합계 검산을 먼저 보여 줍니다.

- 종목 코드를 누르면 화면마다 가는 곳이 다릅니다. 오늘 후보와 명령창은 종목 화면으로, 순위 줄은 그 자리 카드로, 스크리너·변화 목록은 순위 보기 맨 위 카드로 갑니다. 같은 동작의 결과가 달라 사용자가 위치를 잃기 쉽습니다.

## 작업별 흐름

### 1. 아침: "밤새 무엇이 바뀌었나, 급한 것이 있나"

1. 앱을 엽니다. 주소에 해시가 없으면 '오늘'이 열립니다(app.js:739). 클릭 0번. 헤드라인은 새로고침 후 약 4.7초 뒤에 그려집니다(EVIDENCE 전역 사실).
2. 헤드라인을 읽습니다. 예: "먼저 볼 것은 없습니다. 오늘 챙길 것이 1건 있습니다." (01). 아래에 타일 6개와 후보 표가 있습니다.
3. 할 일 목록을 보려면 아래로 약 1화면(약 870 px) 스크롤합니다. '할 일과 알림' 제목은 1440×900 첫 화면의 맨 아래에 걸립니다(01, 02).
4. 점수가 크게 움직인 종목을 보려면: 점수 묶음(1) → 보기가 '오늘 순위'가 아니면 '오늘 순위'(+1) → 50줄 표 아래까지 스크롤(순위 페이지 높이 3,509 px, 열린 카드가 있으면 6,750 px) → 접힌 '점수가 크게 움직인 종목' 펼치기(1). 이 목록은 기본으로 접혀 있습니다(qsf.js:141, 546).

- 클릭·스크롤: 급한 것 확인은 0클릭에 1화면 이하. 점수 변화 확인은 2~3클릭에 약 3,500~6,800 px.
- 막히는 곳: '밤새 바뀐 것'이 오늘 화면에는 '매수 후보 구간에 새로 들어온 종목' 한 줄 정도만 있고(02), 점수 변화 목록은 순위 표 맨 아래 접힌 곳에 있습니다. 헤드라인이 다른 모든 내용을 기다렸다가 4.7초 뒤에 나옵니다. 날짜가 두 형식으로 나옵니다("기준 거래일 2026-11-20 · 26. 11. 23. 오후 12:23 기준", 01·38).
- 심각도: P2 / 확신도: 높음(경로는 코드, 위치는 캡처로 확인).

### 2. "오늘 볼 만한 종목은?" (후보 찾기, 몇 개 비교)

1. 오늘 화면의 '오늘의 후보'에서 스윙·장기 각 5종목을 봅니다(01). 클릭 0번.
2. 종목 칩을 누르면 **종목 화면**이 열립니다(assistant.js:87 → openTicker, app.js:228). 점수 카드가 아닙니다.
3. 점수까지 보려면 종목 화면의 '점수 카드'를 누릅니다(+1, app.js:449). 처음 여는 종목이면 공시를 읽느라 "수십 초 걸릴 수 있습니다"(qsf.js:211).
4. 여러 종목을 견주려면 점수 → 오늘 순위에서 줄을 여러 개 펼쳐 각 카드 사이를 스크롤하거나, 스크리너 표를 정렬합니다(19). '비교' 탭(차트 묶음)은 수익률 선만 비교하고 점수는 비교하지 않습니다(12).

- 클릭·스크롤: 후보 1개의 점수를 보는 데 2클릭에 로딩 대기. 3종목 비교는 3번 펼치고, 펼친 카드마다 화면 2~3개 분량을 스크롤.
- 막히는 곳: (a) 오늘 후보는 '지금 진입 가능'만 거른 목록이어서 순위 1~3위(TECH·TRV·ADP, 모두 '눌림 대기', 18)와 겹치지 않습니다. 이유는 표 아래 작은 글씨 한 줄로만 설명됩니다(01). (b) 오늘 화면은 장기도 "지금 진입 가능 313종목"이라고 씁니다(assistant.js:66). 그런데 점수 탭은 같은 상태를 2026-11-23 사용자 결정에 따라 "진입을 막는 조건 없음"이라고 부릅니다(qsf.js:5-7). 같은 사실이 두 이름으로 나옵니다. (c) 종목 점수를 나란히 보는 화면이 없습니다.
- 심각도: P1 (b 용어 충돌), P2 (a, c) / 확신도: 높음.

### 3. "X 종목은 왜 이 점수인가" (순위에서 설명까지)

1. 점수 묶음(1) → 필요하면 '오늘 순위'(+1) → 표에서 X 줄을 찾아 누릅니다(1). 1440에서 표 첫 줄은 약 690 px 아래에 있어, 첫 화면에는 3줄 정도만 보입니다(17).
2. 줄 아래에 카드가 펼쳐집니다(qsf.js:491-500). 요약 한 문장 → 점수를 올린 요인 / 깎은 요인과 "50 + 19.8 = 69.8" 검산 → 영역 막대 → 진입 순서입니다(22). 이 순서가 좋습니다.
3. 요인 하나하나를 보려면 '요인별 계산' 펼치기(+1). 쉬운 말 설명은 '쉽게 설명해줘'(+1).

- 클릭·스크롤: 2~3클릭. 15위 종목이면 표 안에서 약 1화면 스크롤.
- 막히는 곳: (a) 같은 종목인데 **카드가 두 종류**입니다. 순위 줄에서 펼친 카드는 고른 스타일 하나만 보여 주고 보유 계획이 접혀 있습니다(qsf.js:391-392, planOpen=false). 위원회, 예측 층 FC-1, 점수 이력, 다른 스타일은 없습니다. '평가' 입력이나 '점수 카드'로 연 상세는 두 스타일, 위원회, FC-1, 이력을 모두 담고 순위 **위**에 놓입니다(qsf.js:171, 263-277). (b) 순위 점수는 기록된 공식(QSF-1.4.1), 카드 점수는 지금 공식(QSF-1.5.2)으로 계산합니다. 화면이 이를 알려 주지만(17, qsf.js:487), 숫자가 다를 수 있다는 부담은 사용자에게 남습니다. (c) 명령창에 "AAPL 점수"를 쳐도 점수 카드가 아니라 종목 화면이 열립니다. command.js:36-40은 비교·차트분석만 따로 처리하기 때문입니다.
- 심각도: P2 / 확신도: 높음(a, c는 코드), 보통(b의 실제 영향).

### 4. "이 매수 후보에 지금 들어가도 되나, 얼마나, 손절은 어디" (주문 계획까지)

1. 카드의 '진입'에서 상태와 이유를 봅니다(예: "눌림 대기: … 기준 구간 342.79~349.82", 22). 순위 표의 '진입' 열에도 같은 정보가 있습니다(18).
2. 손절·목표·손익비는 '보유 계획(가설)' 안에 있습니다. 순위 줄 카드에서는 접혀 있어 펼치기(+1), 상세 카드에서는 펼쳐져 있습니다(23). 카드 맨 위 요약 문장에도 손절과 목표가 나옵니다(22).
3. "얼마나"는 다른 곳에 있습니다. 위로 스크롤해 보기 전환(약 270 px 머리 블록 아래) → '주문 계획·모의 장부'(1) → 14열 표에서 X를 눈으로 찾습니다(qsf.js:806). 카드에서 그 줄로 가는 링크는 없습니다. 계좌 기록이 없으면 "계좌 평가액이 없습니다. '내 계좌'에 입금·거래를 기록하면…"이라는 글만 나오고 이동 버튼은 없습니다(20, qsf.js:817).
4. 다른 길은 내 계좌 묶음(1) → 매매 보조(1) → 포지션 크기 계산기에 코드 입력 → 계산(1)입니다(15). 다른 묶음으로 넘어가야 합니다.

- 클릭·스크롤: 5~7클릭. 묶음 사이를 1~2번 오가고, 스크롤은 약 2,000~3,000 px(주문 계획·모의 장부 페이지 높이 2,673 px).
- 막히는 곳: 진입 판단(점수 탭), 수량(주문 계획 보기 또는 매매 보조), 위험 한도(매매 보조의 위험 관리 설정)가 세 곳에 나뉘어 있습니다. 주문 계획은 계좌가 있어야 나오는데, 빈 화면에서 계좌로 가는 길을 글로만 알려 줍니다. 시장 상태 블록(5줄 설명)이 주문 계획과 모의 장부 계획에 또 나와(20) 표가 아래로 밀립니다.
- 심각도: P1 / 확신도: 높음.

### 5. "내가 한 거래 기록 / 보유와 위험 보기"

1. 위쪽 막대의 '내 계좌' 버튼 또는 내 계좌 묶음(1). 하위 탭도 '내 계좌'입니다(13).
2. 보유가 없으면 빈 화면이 "'이미 가지고 있는 종목 추가'를 고르면…"이라고 안내합니다(13, account.js:21). 좋은 안내입니다.
3. '거래 기록 추가' 양식은 첫 화면 아래(약 700 px)에서 시작합니다. 종류·계좌·날짜·코드·구분·수량·가격·손절·목표·메모를 적습니다.
4. 위험은 시장별 자세히(1) 또는 매매 보조의 위험 관리 설정(1)에서 봅니다(14, 15).

- 클릭·스크롤: 기록 1번에 1클릭과 약 1화면 스크롤, 칸 입력 6~10개. 위험 확인에 +1~2클릭.
- 막히는 곳: (a) **거래 기록 양식이 두 개**입니다. 통합 계좌(account.js:130)와 시장별 자세히(portfolio.js:67)에 모두 '거래 기록 추가'가 있고, 첫 안내도 다릅니다. 시장별 화면은 "'거래 기록'에서 입금을 먼저"(14, portfolio.js:36), 통합 계좌는 "이미 가지고 있는 종목 추가"(13)를 권합니다. (b) '모의'가 붙은 장부가 넷입니다. 손으로 적는 '모의 매매'(내 계좌 묶음), 자동 '모의 체결 장부'(점수 → 주문 계획·모의 장부), 위원회의 '모의 성과'(25), 보기 이름의 '모의 장부'. 실제 계좌와 가상 장부를 헷갈릴 위험이 있습니다. 가상 장부에는 '가상의 금액' 배지가 붙어 있어(20) 일부는 막아 줍니다. (c) 날짜 기본값은 미국 계좌일 때 뉴욕 날짜입니다(의도된 동작, 조정자 확인). 시장별 양식은 "날짜(미국 기준)"이라고 적지만, 통합 계좌 양식은 "날짜" 또는 "산 날짜"(account.js:42)만 적어 한국 시간으로 보는 사용자는 하루 차이를 오류로 읽을 수 있습니다. 표시 문제일 뿐입니다.
- 심각도: P2 (a, b), P3 (c) / 확신도: 높음(a, c), 보통(b의 실제 혼동 정도).

### 6. "모델이 통하나, 앞으로의 기록은 무엇을 말하나"

1. 점수 탭 머리의 경고 "점수가 높다고 수익이 더 좋았다는 근거는 아직 확인되지 않았습니다"와 '과거 성적' 접힘(17). 0~1클릭.
2. 보기 '추적·검증'(1): 접힌 6개 묶음입니다. 판정 일정은 "0 / 30 읽음"으로 펼쳐져 있고, 나머지(상위 3 추적, FC-1, 국면 가중치, 미래 자료 차단, 전향 검증)는 각각 +1클릭입니다(21).
3. 검증·기록 묶음(1): '모델'(P6-11B 고정 모델, 26)과 '연구실'(필요 거래일과 남은 기간, 27)(+1).
4. 위원회 보기는 점수 → 투자위원회 → '모의 성과'(+2)입니다.

- 클릭·스크롤: 큰 그림을 잡는 데 5~9클릭, 묶음 2개, 화면 4~5개.
- 막히는 곳: 답이 정직하고 분명합니다("판정 0/30 읽음, 가장 가까운 판정 2027-05 무렵", 21; "남은 기간 약 1.0년", 27). 다만 **'점수 → 추적·검증'과 '검증·기록 → 연구실'이 같은 질문에 나눠 답합니다.** 이름도 비슷해 어느 쪽이 무엇인지 기억해야 합니다. 빈 상태 일부는 터미널 명령을 안내합니다. 예: "`python app.py qsf scan` 또는 매일 자동 실행 후 표시됩니다"(qsf.js:463), "상세: `python app.py qsf validate`"(qsf.js:990). 사용자는 명령보다 버튼을 원합니다(사용자 결정 기록).

### 7. 390 px 휴대폰에서 같은 아침 확인

## 강점

- 첫 화면이 결론부터 말합니다. 헤드라인 문장과 할 일 수준(ACT/DUE/INFO)이 있고, 항목마다 갈 곳 버튼이 있습니다(01, 02).
- 카드가 "왜"에 바로 답합니다. 요약 한 문장, 점수를 올린 요인·깎은 요인, 50 기준 합계 검산이 있고, 쉬운 말 설명은 따로 엽니다(22).
- 정직한 표시가 많습니다. 신뢰도는 '자료의 양'이라고 밝히고, 시장 상태는 '점수 미반영', 가상 장부는 '가상의 금액', 판정은 "0/30 읽음"으로 보여 줍니다. 기록이 쌓이기 전에는 결론을 내지 않는다는 점이 화면마다 일관됩니다.
- 순위 줄을 누르면 그 자리에서 펼쳐져 순위 속 위치를 잃지 않습니다. 점수 탭에 돌아오면 스크롤 위치와 펼친 줄을 되살립니다(qsf.js:193-204).
- 명령창은 탭 별칭, 최근 종목, 문장 질문을 받습니다. 종목 주소(#stock/코드, #qsf/코드)는 뒤로 가기와 새로고침에도 남습니다.
- 빈 상태 대부분이 다음 행동을 알려 줍니다(13, 14, 20).
- 모의 장부에는 '가상의 금액 · 주문을 보내지 않습니다' 배지가 있어 실제 계좌와 구분됩니다(20).
