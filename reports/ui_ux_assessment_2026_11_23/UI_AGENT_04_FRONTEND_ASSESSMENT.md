# UI 에이전트 4 — 프론트엔드 구조·디자인 시스템 평가 (2026-11-23)

작성: 프론트엔드 아키텍트 / 디자인 시스템 엔지니어 관점. 읽기 전용 점검이며 이 보고서 외에는 어떤 파일도 고치지 않았습니다. 서버나 브라우저는 열지 않았고, 화면은 coordinator의 증거 묶음(EVIDENCE.md, shots/)만 봤습니다. 숫자는 모두 `grep`/`wc`로 직접 센 값이며, 세는 방법을 함께 적습니다.

## 1. 요약

- **색만 토큰이고 나머지는 토큰이 없습니다.** `:root`에 색 토큰 30개(의미 색 12, 시리즈 8, 이동평균 10)가 있고 밝게/어둡게 전환은 깔끔하게 동작합니다(shots 22 ↔ 29 비교: 같은 화면이 토큰 교체만으로 바뀜). 반면 글자 크기 12종, 모서리 8종, padding 39종, margin 46종, 그림자 4종이 모두 숫자로 박혀 있습니다.
- **재사용 컴포넌트 층이 없습니다.** 표 77개, 패널 116개, 안내 상자 39개, 빈 상태 62개, 세그먼트 스위치 13개가 21개 JS 파일 안의 템플릿 문자열로 매번 새로 쓰였습니다. 함수로 묶인 것은 `badge()`, `card()`, `meta()`, `errBox`, `spark()`, `setupCanvas()`, `plainBlock()` 정도입니다.
- **인라인 스타일 261개 가운데 160개가 `class="meta" style="margin:0"` 한 가지 패턴**입니다. 블록용 `.meta`(margin-top 8px)를 줄 안에서 쓰려고 매번 덮어쓰는 것입니다. 수정자 클래스 하나면 60%가 사라집니다.
- **CSS는 기능이 생길 때마다 뒤에 붙인 구조**입니다(구역 주석 18개). 겹치는 선택자 3개, 쓰이지 않는 선택자 약 9개, 화면 폭 기준(breakpoint) 5종(560/600/700/720/760)이 섞여 있습니다.
- **이스케이프 습관은 좋습니다**(`esc(` 864회). 위험은 낮지만 "미리 만든 HTML 문자열을 넘기는" 관례에 기대고 있어 자동으로 막아 주지는 않습니다.
- **재설계는 프레임워크 없이 가능합니다.** 다만 테스트 24개 파일이 정적 파일의 소스 문자열을 고정하고 있어(약 180개 문자열 단언), 리팩터링마다 테스트를 같이 고쳐야 한다는 점이 가장 큰 비용입니다.
- 제안 점수: **Consistency·frontend 4.5 / 10** (근거는 8절).

## 6. 강점

- **빌드 없이 돌아가는 단순함.** 21개 스크립트, 프레임워크 0, 외부 라이브러리 0(app.js:1). DOMContentLoaded 81 ms(EVIDENCE). Mac과 폰 모두에서 같은 파일이 그대로 돕니다.
- **색 토큰과 테마 전환이 제대로 되어 있음.** 자동/밝게/어둡게 3단계(app.js:341-349), 캔버스도 토큰을 다시 읽어 그림. 밝은 화면(29)과 어두운 화면(22)이 같은 구조로 깨끗하게 바뀝니다.
- **이스케이프 습관.** `esc()`가 864회, 서버 문장을 넣는 곳은 거의 다 감싸고 있음. 서버의 오류 코드를 한국어 문장으로 바꾸는 표(app.js:78-111)도 있음.
- **몇몇 좋은 공유 부품.** `card()`를 시장 개요와 오늘 탭이 같이 씀, `spark/setupCanvas/line`, `plainBlock`, `qsfMarketState`, `badge`.
- **탭 등록 방식.** `RENDER`/`RETURN`/`ALWAYS_FRESH`(app.js:699-701)로 파일마다 자기 탭을 등록 — 가벼운 플러그인 구조라 재설계 때 단위로 쓰기 좋음.
- **비동기 경합 처리.** 요청 표식(`rankToken`, `evalToken`, `sug.token`)과 `mk !== state.market` 검사가 거의 모든 렌더에 있음.
- 전역 이름 충돌 0건(확인), 같은 id 중복은 committee.js:186/219의 1건뿐(서로 다른 분기로 보임).
- 접근성의 씨앗: 스크리너 정렬 `aria-sort`(qsf.js:616), 순위 줄 `:focus-visible`(style.css:415), 터치 기기 최소 높이 40px(style.css:376-380).

## 7. 재설계 시 단계 제안

원칙: 프레임워크로 옮기지 않습니다. 이 앱은 빌드 없이 Mac에서 돌고 같은 Wi-Fi의 폰에서도 열려야 하며 CDN에 기대면 안 됩니다. React/Vue 이전이 얻는 것(컴포넌트, 상태)은 아래 작은 도구로 대부분 얻을 수 있습니다. 각 단계는 따로 커밋할 수 있고, 단계마다 점수·계산은 건드리지 않습니다.

0. **준비 (반나절)** — 기준 스크린샷(shots/의 40장)을 고정. F20의 테스트 중 CSS/JS 문자열을 고정하는 단언 목록을 뽑아 "이 단계에서 같이 고칠 테스트"로 표시.
1. **토큰 (하루)** — style.css 맨 위에 글자 7단계, 간격 6단계, 모서리 4종, 그림자 2종, z-index 4단계, `--content-max`, `--hover`, `--on-accent` 추가. 기존 숫자를 토큰으로 바꾸되 값은 가장 가까운 단계로(12.5px → 12 또는 13). 결과: 글자 크기 12종 → 7종.
2. **`ui.js` 부품 (2–3일)** — app.js 앞에 로드. `html\`\``(자동 이스케이프) + `raw()`, `ui.panel`, `ui.table({cols, rows, empty})`, `ui.notice`, `ui.empty`, `ui.seg`, `ui.fold`(`<details>` 기반), `ui.kv`, `ui.badge(text, tone)`, `ui.tip.place(e)`, `fmt.*`(단일 `DASH`). 작은 파일(calendar, peers, alerts, coin, sectorpicks)부터 옮겨 부품을 검증하고, qsf.js는 마지막에.
3. **인라인 스타일 제거 (하루)** — `.meta-i` 하나로 160개, 남은 약 100개는 유틸리티 6–8개로. 동적 값(`width:${…}%` 26곳)은 남겨도 됨.
4. **CSS 재배치 (하루)** — 토큰 → 기본 → 레이아웃 → 컴포넌트 → 화면별 → 반응형. 죽은 규칙·중복 선택자 삭제, 화면 폭 기준 2단계로 통일, 768px 태블릿 규칙 추가. 한 파일을 유지해도 되고 `<link>` 여러 개로 나눠도 빌드는 필요 없음.
5. **동작 정리 (하루)** — 접기 `<details>`로 통일, 탭 ARIA, 클릭 요소를 버튼/링크로, `redrawers`를 이름 키로, 오늘 탭에 `RETURN` 적용, 날짜 라벨 통일, 저장 키 접두사.
6. **(선택, 나중) ES 모듈** — `<script type="module">`은 빌드 없이 Mac Safari/Chrome과 최신 폰 브라우저에서 동작. 전역 459개를 정리할 수 있으나 파일 간 `import`를 모두 적어야 하므로, F20의 소스 고정 테스트를 줄인 뒤에만 권합니다.

## 9. 확인하지 못한 것

- 실제 렌더 성능(페인트 시간, 메모리 증가, `redrawers` 누적 효과)은 측정하지 않았고 코드로만 추론했습니다(F14, F16).

- 쓰이지 않는 선택자 목록(F6)은 `grep`으로 찾았으므로 `${…}`로 조립되는 클래스명이 있으면 틀릴 수 있습니다(`g-B`, `info`는 동적이라 목록에서 뺐습니다).

- `"…" in js/css` 단언 약 180개 중 정적 파일을 대상으로 하는 것만 정확히 센 값은 없습니다(F20).
- 실제 폰 기기에서의 표시는 보지 못했습니다(증거의 390px 에뮬레이션 화면만 참고).
