# 기술과 자료 평가 (2026-11-22)

근거: `AGENT_01_SOFTWARE_ARCHITECTURE.md`, `AGENT_05_DATA_INTEGRITY.md`, 두 건의 교차 검증, 종합 평가자의 전체 테스트와 일치 시험. 분류 표시는 VERIFIED(직접 실행하거나 코드 경로를 끝까지 읽음), PARTIALLY VERIFIED, UNVERIFIED, FAILED.

## 1. 구조

실제 실행 흐름(VERIFIED):

```
원자료(야후·SEC·DART·KRX·한국은행) → 저장본(terminal/cache.py) → 그날 자료가 왔는지 판정(markets/session_data.py)
→ 지표(technicals.py)와 재무 수치(fundamentals.py) → 요인(factors.py) → 점수와 차단 조건(engine.py)
→ 카드(service.card: 진입 상태, 보유 계획, 엇갈림 안내) → 원장(ledger.py) 또는 화면
```

- 스캔(`QSF.scan`)과 직접 평가(`QSF.evaluate`)는 같은 `context` → `card` → `engine.score`를 쓴다. 과거 시험 코드도 같은 `engine.score`를 부른다.
- 약 35,000줄, 테스트 약 1,820개 함수(매개변수 전개 뒤 2,014건). 개인 도구치고 크다. 전향 기록 모듈 약 30개가 그 무게의 큰 부분이고, 각각은 작지만 유지할 대상이 많다.
- 설정은 `config.py`에 모여 있다고 안내서에 적혀 있지만, 요인의 기준값은 `factors.py`에, 진입 규칙은 `holding.py`에 있다(모듈 상수 771개 중 41개만 `config.py`).

## 2. 백엔드와 프런트엔드

- 백엔드: 표준 라이브러리 HTTP 서버 하나, 외부 의존은 `yfinance`·`numpy`·`pandas` 정도. 서버 없이 기기에서 돈다는 목표에 맞다.
- 프런트엔드: 빌드 도구 없는 정적 자바스크립트. 화면 함수가 서버 응답을 그대로 그린다. 오류 문구는 약 30개 코드 중 5개만 한국어로 준비돼 있다.
- 다른 기기에서 쓰려는 계획에 대해: 서버가 127.0.0.1에만 묶여 있고 다른 호스트 이름을 거절한다. 화면에는 좁은 폭 규칙이 다섯 개뿐이고 설명 66개가 마우스를 올려야 보인다. 지금은 휴대폰에서 쓸 수 없다.

## 4. 시점 기준 무결성

- 재무는 공시일 기준으로 읽는다(미국 SEC 제출일, 한국 DART 접수일). VERIFIED.
- 한국 과거 시험은 그날의 KRX 파일로 대상·가격·시가총액을 만들고 상장폐지 종목을 포함한다(2019년 점수 받은 종목의 8.3%가 지금 거래되지 않음). VERIFIED. 남은 치우침(배당 제외, 거래정지 종목은 마지막 거래가)은 점수에 불리한 쪽이다.
- 미국 과거 시험은 치우쳐 있다(BIASED). 오늘의 구성 종목과 오늘의 업종 분류를 과거에 적용했고, 되살린 종목의 가격은 2017-03까지만 있으며, 실제 구성 종목의 78.8%만 담는다. 미국의 "근거 없음"은 "없다고 확인됨"이 아니라 "보이지 않음"이다.
- 미래 참조 점검은 오늘 점수 엔진을 대상에 넣었지만, 그 항목은 구조상 실패할 수 없다(점검이 엔진에 그날까지의 행만 넘긴다). 저장된 점검 결과(11월 20일)에는 아직 들어 있지도 않다. 이 항목을 "엔진이 점검됐다"는 근거로 쓰면 안 된다. 종합 평가자가 오늘 넣은 것이다.
- DART의 정정 공시가 원래 접수일로 저장되는지는 확인하지 못했다(UNVERIFIED).

## 5. 신뢰성

- 전체 테스트: 커밋 `b5ca247`의 별도 사본에서 2,014개 통과, 실패 0, 건너뜀 6(실제 제공자 접속), 287초. `evidence/chief/pytest_summary.txt`. 통과는 "코드가 설계대로 동작한다"까지만 말한다.
- 원본 문장을 고정해 둔 테스트가 약 77개(4%)다. 동작이 아니라 글자를 지키므로 공식이나 문구를 바꿀 때마다 하나씩 깨진다(오늘 다섯 번).
- 조용히 지나가는 실패(코드로 확인, 재현하지 않음):
  - 자료를 못 읽은 보유 종목이 매일 알림에서 빠진다(`automation.py:874-876`).
  - 스캔 오류가 10% 미만이면 표시 없이 기록된다(`service.py:937-938`).
  - 투자위원회·기대치 기록이 멈춰도 알리지 않는다(손상만 감시).
  - 실적일 조회가 실패하면 스윙의 실적 임박 차단이 꺼진다(`service.py:749-752`).
  - 미래 참조 점검이 실패해도 화면에는 이전의 "정상" 파일이 남는다.

## 6. 기술 부채

| 항목 | 영향 |
|---|---|
| 구간 기준(80/70/55/40)이 일곱 곳에 숫자로 적힘 | 오늘의 완충 규칙이 주문 계획의 구간 표시에는 닿지 않았다 |
| 31개 파일이 원장의 내부 함수(`_live_rows`, `_load`)를 직접 부름 | 원장 형식을 바꾸기 어렵다 |
| 한국 기록 600건의 가격 출처가 "Yahoo Finance 일봉"으로 고정 | 실제로는 KRX로 만든 일봉. 표시 오류 |
| `terminal/qsf/`에 로그 없음 | 실패 원인은 예외 이름만 남는다 |
| 화면 머리말이 아직 "QSF 1.1" | 표시 오류 |
| 업종 비율 비교가 지금 비어 있음 | 지금 버전(1.5.0)으로 기록된 날만 읽기 때문. 버전을 올릴 때마다 첫 기록까지 빈다 |
| `.env` 권한 | 사용자가 그대로 두기로 정함. 재론하지 않는다 |
