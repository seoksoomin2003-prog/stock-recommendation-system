# AGENT 6: 통계 검증과 백테스트 평가 (2026-11-22)

평가 대상: 커밋 `b5ca247`, 모델 QSF-1.5.0. 담당 범위는 "투자 방법이 예측력을 보였는가"와 "앞으로 그것을 판정할 장치를 믿을 수 있는가", 그리고 시스템 시험 F(과거 결과의 재현성)다.

**먼저 밝힌다.** 이 평가에서 원장, 전향 기록, 가격 이력으로 새로 계산한 수익률, IC, 성과 수치는 하나도 없다. 이미 실행된 시험의 결과 파일을 읽었고, 판정 통계는 난수로만 모의실험했다. 이 프로젝트의 사전 등록 규칙(시험은 한 번, 전향 기록은 정해진 날 전에 열지 않음)을 지키는 것이 평가의 일부이기 때문이다.

## 2. 필수 질문에 대한 답

### 질문 1. 검증 틀이 동작하는가?

**답: 그렇다. 개인용 프로그램으로는 드물게 엄격한 틀이 있고 실제로 돈다. 다만 틀의 일부에 빈 곳이 남아 있다.** 분류: VERIFIED(읽은 코드와 실행 결과 기준).

근거:
- **사전 등록과 한 번 실행.** 규칙 문서가 결과보다 먼저 커밋됐다. 네 건을 직접 확인했다(`git log --diff-filter=A`): 한국 재현 규칙 14:53 → 결과 16:38(2026-11-10), QSF 1.2 검증 15:35 → 16:43, 한국 가격 신호 01:30 → 04:03, 상위 3 모의 14:42 → 14:52. 나머지는 이전 감사의 확인에 기댄다(PARTIALLY VERIFIED). 커밋 전에 기록 없이 돌려 본 적이 없다는 것은 Git으로 증명할 수 없다(UNVERIFIED).
- **다시 읽기를 코드가 막는다.** `live_forward.evaluate_once`는 결과 파일이 있으면 거부하고(`live_forward.py:191-192`), 만기 거래일이 모자라면 거부하며(`:200-201`), 더 쌓인 뒤에 돌려도 처음 240개(또는 756개)만 쓴다(`:202`). 원장 검증이 실패하면 판정하지 않는다(`:194-195`).
- **판정 조건이 순위와 돈을 나눈다.** 조건 A(IC 0.02 이상, t 기준, 전·후반 IC, 비용 후 상·하위 수익, 매수 구간 초과수익)와 조건 B(매수 구간이 지수를 전·후반 모두 이김)를 따로 본다(`validate.py:261-269`, `live_forward.py:139-151`). "순위는 맞지만 돈은 못 벌었다"를 `RANK_ONLY`로 따로 부르는 것은 올바른 설계다.
- **수익 계산이 보수적이다.** 진입은 기록 뒤의 다음 거래일 시가, 청산은 h번째 종가, 왕복 비용 차감, 거래가 끊긴 종목은 마지막 거래가에 판 것으로 친다(`ledger.py:374-419`, `outcome`).
- **걸어가기 검증 도구**가 있고 겹치는 구간을 잘라 낸다(`walkforward.py:10-34`). 국면 가중치 시험에 실제로 쓰였고 기록된 점검값은 한국 64구간, 미국 128구간 모두 누출 없음이다(`data/qsf/lookahead_audit.json`).
- **실행 중인 터미널이 일정을 보여 준다.** `/api/qsf/readings` 응답: 판정 30건, 읽은 것 0건, 주된 판정 4건, 스스로 적용하는 것 4건(재무 기준 기간 2, 순위 규칙 2).

빈 곳은 4절에 있다. 핵심은 세 가지다: 투자 비중이 실력과 섞이는 문제가 스스로 적용하는 판정에 남아 있고, 보정되지 않은 판정 문구가 두 곳 있으며, 미래 참조 점검의 범위가 좁다.

## 10. 개선 우선순위

**P0 (판정이 잘못된 결정을 스스로 내리지 않게)**
1. 순위 규칙 장부(RK-1)를 회전율 장부처럼 "알리되 스스로 적용하지 않음"으로 바꾸거나, 채택 조건을 투자 비중을 맞춘 비교(같은 투자 비중으로 환산한 수익 차이, 또는 지수 노출을 회귀로 뺀 차이)로 바꾼다. 아직 5거래일 기록이라 수익을 보기 전이다.
2. 공식 변경 규칙을 미리 정한다: 주된 판정이 끝날 때까지 점수 공식을 얼리거나, 바꾸면 시작일을 옮긴다는 것을 지금 규칙 문서에 고정한다. 바꾸고 싶은 것은 도전자 기록으로 나란히 적는다(이미 있는 장치다).

**P1 (문구와 범위)**
3. 두 시장 합산 참고값을 보정하거나(두 t값 합의 우연 분포를 `calibrate`로 계산) 삭제한다.
4. 상위 3 추적의 판정 문구를 `plain_bar`로 보정하고 판정 일정에 "참고"로 올리거나, 판정 문구를 없애고 수치만 남긴다.
5. 미래 참조 점검에 재무 경로(공시일 뒤의 수치를 지워도 점수가 그대로인지)와 미국을 넣고, 엔진을 포함한 점검이 실제로 기록됐는지 확인한다.
6. `QSF_LIVE_FORWARD_POWER_2026_11_11.md`에 새 기준의 표를 덧붙인다(이 문서 3.4절의 값). 화면의 "판정 일정"에 "이 판정은 IC 약 0.10 이상만 잡습니다"를 한 줄로 적는다.

**P2 (지식의 빈 곳, 새 시험 구간이 필요 없는 것)**
7. 이미 저장된 결과로 만들 수 있는 견고성 표: 날짜 블록 부트스트랩 신뢰구간, 십분위 단조성. 단, 새 시험이 아니라 기존 결과의 재표현임을 적고 판정을 바꾸지 않는다. 사전 등록 규칙과 충돌하는지 먼저 사용자와 정한다.
8. 한국의 재무 기준 기간 판정을 상위 20%로 읽도록 맞추거나, 한국은 답할 수 없다고 규칙 문서에 적는다. 한국 지수의 배당 불일치를 실전 판정 규칙의 "알려진 한계"에 적는다.
9. 원장 색인 줄에 코드 커밋을 적고, 색인의 마지막 해시를 하루 한 번 바깥(예: 매일 알림 문구, Git 커밋)에 남긴다.

**P3 (자료가 생기면)**
10. 미국의 상장폐지 종목 자료(무료 키가 필요하다고 조사돼 있음)를 얻으면 새 규칙 문서로 한 번 시험한다.
11. 화면의 예상 시점 계산에 휴장일을 넣는다. 전향 판정의 비용을 규칙 문서에 고정한다.
