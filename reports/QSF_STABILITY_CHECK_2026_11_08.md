# 안정성 점검 (2026-11-08)

점수 수식, 라이브 점수, 원장은 바꾸지 않았습니다. 지운 파일도 없습니다.

## 고친 문제

| 문제 | 영향 | 조치 |
|---|---|---|
| **미국 휴장일에 한국 작업이 멈춤** | 일일 작업이 미국 세션 기준이라, 미국만 쉬고 한국이 거래한 날은 `UP_TO_DATE`로 끝났습니다. 그날 한국 스캔은 영구히 빠지고 전향 기록은 늦은 기록이 됩니다. 연 약 10일로 추정합니다. | 평일마다 한 번은 한국 3단계(`QSF_KR`, `NEWS_KR`, `KR_FORWARD`)를 실행합니다. |
| **한국 추적 원장이 백업에서 빠짐** | 해시 사슬로 묶인 `tracking/kr/ledger/observations.jsonl`이 백업 대상에 없었습니다. | 대상에 넣었습니다. |
| **미국 도전자 일별 파일이 백업에서 빠짐** | 색인만 복사되고 기록 파일은 복사되지 않을 상태였습니다. 첫 파일이 생기기 전에 찾았습니다. | 대상에 넣었습니다. |
| **백업이 다음 세션까지 밀림** | 백업은 세션당 한 번이라, 그 뒤 슬롯에 쓰인 한국 기록은 하루 늦게 백업됐습니다. 전향 기록 파일이 백업에 하나도 없는 상태였습니다. | 어떤 단계든 실행되면 마지막에 백업합니다. 지금까지의 기록도 백업했습니다. |
| **디스크 경고 없음** | 스캔 시세 캐시(`scanbars`)가 세션당 약 50MB, 한 달 약 1GB씩 늘고 지우는 규칙이 없습니다. 여유는 8.2GB입니다. | 5GB 미만이면 경고, 2GB 미만이면 긴급으로 일일 요약과 기록 현황에 표시합니다. |
| **테스트가 디스크를 약 2.4GB 사용** | 전체 테스트가 데이터를 2벌 복사해, 디스크가 빠듯할 때 자동 실행과 부딪힐 수 있었습니다. | APFS 복제로 바꿨습니다. 전체 테스트 중 여유 감소가 약 9MB입니다. 복제본은 쓰는 순간 분리되므로 보호 기능은 같습니다. |

## 추가한 기능
- **복원 시험:** `.venv/bin/python app.py qsf backup-check`. 최신 백업을 임시 폴더에 복원하고 각 기록의 검증을 돌립니다.
- **백업 경고:** 마지막 백업이 4일을 넘으면 기록 현황에 경고합니다. 디스크 여유와 마지막 백업일도 표시합니다.
- **캐시 보고:** `.venv/bin/python app.py qsf cache-report`는 읽기만 합니다.
- **캐시 정리:** `.venv/bin/python app.py qsf cache-prune --apply`는 최근 5개 세션보다 오래된 `scanbars` 파일만 지웁니다. **실행하지 않았고 예약에도 넣지 않았습니다.**

## 확인 결과
- **복원 시험 통과:** 전향 기록 4곳, QSF 원장 9개 조각, 해시 사슬 파일 5개를 복사본에서 검증했고 모두 정상입니다.
- **API 점검:** 읽기 API 73개에서 500 오류가 없습니다. 400 응답은 잘못된 입력을 거절한 경우입니다.
- **테스트:** 전체 1553개 통과, 6개 건너뜀, 6개 예상된 실패(xfail).

## 확인하지 못한 것
- 미국 휴장일 처리는 테스트로만 확인했습니다. 실제 다음 미국 휴장일은 2026-11-26입니다.
- 위 "연 약 10일"은 미국 휴장일 수로 어림한 값입니다. 양국 휴장이 겹치는 날을 빼서 계산하지 않았습니다.
- `/api/qsf/validation`이 첫 호출에 약 32초 걸렸습니다. 다른 API 오류는 아니며, 원인은 아직 보지 않았습니다.
- 2026-11-04의 도전자 기록은 빠진 채로 남습니다. 소급 기록하지 않는 규칙이고, 원인은 당시 로그가 없어 알 수 없습니다.
