# 운영 안내서: Claude 없이 이 프로그램을 쓰는 법 (2026-11-16)

이 문서는 프로그램을 고쳐 주는 사람이 없을 때를 위한 것이다. 매일 할 일은 없다. 아래는 무엇이 저절로 돌아가는지, 무엇을 가끔 보면 되는지, 안 될 때 무엇을 누르면 되는지다.

## 1. 저절로 되는 것

| 일 | 언제 | 사람이 할 일 |
|---|---|---|
| 자료 수집과 점수 기록(미국·한국), 뉴스, 모의 장부, 비교 장부, 백업 | 매일 07:10부터 23:10까지 매시 10분에 시도. 그날 할 일이 끝났으면 건너뜀 | 없음 |
| 터미널 서버(화면, `http://127.0.0.1:8765`) | 맥이 켜지면 저절로 뜨고, 죽으면 저절로 다시 뜸 | 없음 |
| 하루 요약 알림 | 매일 작업이 끝나면 텔레그램으로 | 읽기 |
| 판정(아래 4절) | 기록이 충분해진 날 매일 작업이 스스로 읽고 텔레그램으로 알림 | 없음 |

**조건은 하나다: 맥이 켜져 있고, 전원에 연결돼 있고, 깨어 있어야 한다.** 배터리로 잠든 맥은 작업을 하다 끊긴다. 맥이 꺼져 있던 날의 점수 기록은 비고, 나중에 채울 수 없다. 켠 뒤부터 다시 이어지며, 판정은 그만큼 늦어질 뿐 틀어지지 않는다.

## 2. 가끔 볼 것

- **텔레그램 하루 요약.** "실패"가 적힌 단계가 있어도 다음 시간에 저절로 다시 시도한다. 같은 단계가 사흘 넘게 실패하면 5절을 본다.
- **화면 맨 위 상태 줄.** 서버 오류 수, 기록이 밀린 날이 있으면 여기에 나온다.
- **점수 탭 → 추적 → 판정 일정.** 모든 판정이 언제쯤 읽히는지, 읽힌 것은 결과가 무엇인지 한 표로 나온다.
- **점수 탭 → 주문·모의 장부.** 모의 장부와 두 비교 장부(회전율 규칙, 순위 규칙)의 진행 상황.

## 3. 안 될 때 누를 것

| 증상 | 할 일 |
|---|---|
| 화면이 열리지 않는다 | Finder에서 프로젝트 폴더의 `ops/서버 다시 시작.command`를 두 번 누른다. 그래도 안 되면 맥을 다시 켠다 |
| 아침에 새 기록이 없다 | 화면 맨 위의 **지금 수집** 버튼을 누른다(15~25분, 길면 두 시간). 화면이 안 열리면 `ops/지금 수집.command`를 두 번 누른다 |
| 텔레그램이 오지 않는다 | 화면이 열리고 기록이 쌓이고 있으면 알림만 끊긴 것이다. `.env`의 텔레그램 값 두 개를 확인한다 |
| "디스크 여유 부족" 알림 | 다른 파일을 지워 공간을 만든다. `research_data/`와 `data/` 안의 파일은 지우지 않는다 |
| 맥을 새로 샀다 | 프로젝트 폴더 전체와 `~/QuantEngineBackups`를 옮긴다. 자동 실행 등록은 사람 손이 필요하다(6절) |

## 4. 판정: 스스로 읽히는 것과 그 뒤

판정은 기록이 쌓여야 읽을 수 있다. 대부분 2027년 10~11월, 장기 판정은 2029년 말이다. 읽히는 날 텔레그램으로 결과 코드와 뜻이 온다. 결과 파일은 `reports/qsf/`에 한 번 적히고 다시 읽지 않는다.

**스스로 규칙까지 바꾸는 판정은 두 가지뿐이다.**

| 판정 | "적용"이 되는 조건 | 적용되면 | 뒤집는 법 |
|---|---|---|---|
| 회전율 규칙 비교(한국·미국) | 비교 장부의 비용이 더 낮고, 하루 수익률 차이의 평균이 0 이상 | 모의 장부, 실제 계좌 주문 계획, 보유 판단이 두 규칙을 씀(손절 뒤 20거래일 재진입 대기, 스윙 30거래일 뒤 점수 55 이상이면 계속 보유) | `.env`에 `QSF_TURNOVER_RULES=off` |
| 순위 규칙 비교(한국·미국) | 하루 수익률 차이의 평균이 0보다 크고 t가 2.0 이상 | 같은 세 곳이 두 규칙을 씀(진입은 그날 점수 상위 20% 안, 장기 보유는 상위 50% 밖이면 매도) | `.env`에 `QSF_RANK_RULES=off` |

`on`으로 두면 판정과 상관없이 항상 적용한다. 값을 지우거나 `auto`로 두면 판정을 따른다. `.env`를 고친 뒤에는 `ops/서버 다시 시작.command`를 누른다.

**나머지 판정 20개는 결과만 알려 주고 아무것도 바꾸지 않는다.** 모든 계획서가 "자동으로 바꾸지 않는다"고 정해 두었기 때문이다. 결과를 읽는 법:

| 판정 | 좋은 결과가 나오면 뜻하는 것 | 나쁜 결과가 나오면 |
|---|---|---|
| 실전 점수 판정(스윙·장기 × 한국·미국) | `WEAK_POSITIVE_EVIDENCE`: 점수가 높은 종목이 실제로 나았다는 약한 근거. 그 점수를 더 믿어도 된다 | `NO_EVIDENCE`: 그 점수의 순위를 수익의 근거로 쓰지 않는다. 화면의 점수는 참고로만 본다. `RANK_ONLY`: 순위는 맞지만 상위 종목이 비용을 넘지 못했다 |
| 한국 회피 표시 | `AVOID_RULE_SUPPORTED`: 회피 표시가 붙은 종목은 직접 피한다 | 표시는 참고로만 본다 |
| 점수 분리 비교 | `SPLIT_BETTER`: 지금 점수가 낫다 | `WITH_REGIME_BETTER`: 시장 국면을 넣은 이전 점수가 나았다. 되돌리려면 코드 수정이 필요하다(7절) |
| 한국 스캔 대상 두 건 | 지금 대상(시가총액 상위 300)이 지지된다 | `FORMER_BETTER`: 이전 대상이 나았다. 되돌리려면 코드 수정이 필요하다 |
| 한국 이전 스윙 공식 | `DECISION_SUPPORTED`: 지금 공식이 지지된다 | `PRIOR_BETTER`: 이전 공식이 나았다. 되돌리려면 코드 수정이 필요하다 |
| 미국·한국 도전자 점수, 한국 가격·재무·공시 점수, 독자 매매법 | 그 점수나 매매법에 근거가 생겼다. 지금 점수에 넣으려면 코드 수정이 필요하다 | 아무것도 하지 않는다 |
| 국면 가중치 기록 읽기 | 판정 없이 수치만 적는다 | |

"구분되지 않음", "근거 없음"은 나쁘다는 뜻이 아니라 240거래일로는 알 수 없었다는 뜻이다. 그때는 지금 그대로 쓰면 된다.

## 5. 프로그램이 스스로 고치지 못하는 것

- **자료를 주는 곳이 형식을 바꾸거나 막는 경우**(Yahoo, KRX, DART, SEC, FRED, ECOS). 그 단계만 "실패"로 남고 다른 단계는 계속 돈다. 사흘 넘게 같은 단계가 실패하면 코드를 고칠 사람이 필요하다. 그동안 그 시장의 점수는 새로 기록되지 않고, 화면은 마지막 기록을 날짜와 함께 보여 준다(오래된 자료를 새것처럼 보여 주지 않는다).
- **키가 막히거나 만료된 경우**(`.env`의 DART, KRX, ECOS, 텔레그램 값). 해당 사이트에서 다시 받아 `.env`에 넣는다. 키 값은 누구에게도 보내지 않는다.
- **기록 검증 실패 알림.** 기록 파일이 손상됐다는 뜻이다. 파일을 고치거나 지우지 말고, 백업(`~/QuantEngineBackups` 또는 `.env`의 `QPP_BACKUP_DIR`)의 같은 파일과 바꿀 사람이 필요하다. 그 기록의 판정은 읽히지 않고 알림만 온다.
- **"기록은 충분한데 15번 읽지 못했습니다" 알림.** 어떤 판정이 조건을 못 채워 계속 거절되고 있다는 뜻이다. 이후에는 일주일에 한 번 다시 시도한다. 이유는 `data/automation/logs/`의 그날 파일에 있다.
- **macOS를 크게 올린 뒤 아무것도 돌지 않는 경우.** 파이썬 환경(`.venv`)이 깨졌을 수 있다. 고칠 사람이 필요하다.

## 6. 하지 말 것

- `research_data/`, `data/`, `tracking/` 안의 파일을 지우거나 고치거나 옮기지 않는다. 기록은 한 번 적고 고치지 않는 것이 이 프로그램의 근거다.
- `reports/qsf/`의 결과 파일을 지워서 판정을 다시 읽게 하지 않는다. 한 번만 읽는다는 규칙이 깨진다.
- 밤에(자료 수집 시간대에) 자동 실행을 다시 등록하지 않는다. 등록(`python app.py automation install`)은 낮에, 매일 작업이 돌고 있지 않을 때만 한다.
- 판정이 나오기 전에 `QSF_TURNOVER_RULES`나 `QSF_RANK_RULES`를 `on`으로 두지 않는다. 비교가 무의미해진다.
- 이 프로그램은 주문을 보내지 않는다. 화면의 주문 계획과 점수는 계산 결과이고 투자 자문이 아니다.

## 7. `.env`에서 바꿀 수 있는 것과 코드 수정이 필요한 것

| 바꿀 것 | 방법 |
|---|---|
| 회전율 규칙, 순위 규칙을 켜고 끔 | `.env`의 `QSF_TURNOVER_RULES`, `QSF_RANK_RULES` (`auto` / `on` / `off`) |
| 백업 위치 | `.env`의 `QPP_BACKUP_DIR`. iCloud Drive나 외장 디스크로 두면 디스크가 고장 나도 기록이 남는다(지금은 같은 디스크) |
| 계좌 금액(기준 모델용) | `.env`의 `QPP_CAPITAL`, `QPP_CAPITAL_KRW` |
| 위험 한도, 종목 비중 한도, 장기·스윙 비율 | 화면의 포트폴리오 탭 설정 |
| 점수 공식, 스캔 대상, 진입 기준, 미국 나쁜 날 크기 절반 규칙 | 코드 수정이 필요하다. `terminal/qsf/config.py`에 모여 있다. 바꿀 때는 버전을 올리고 `reports/DECISIONS_FOR_USER.md`에 적는다 |

코드를 고칠 사람(또는 다른 AI 도구)에게는 이 문서와 `reports/DECISIONS_FOR_USER.md`, 그리고 해당 계획서(`reports/*_PROTOCOL.md`)를 먼저 읽게 한다. 고친 뒤에는 `.venv/bin/python -m pytest -q`가 모두 통과해야 한다.
