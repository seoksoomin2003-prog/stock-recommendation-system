# 코인 파트 설계안 (2026-11-21)

사용자 요청: "코인 부분도 넣을 거야. 엔진 설계해, 점수 알고리즘은 어떻게 설계해야 할지도. 미국/한국/코인 이렇게 선택할 수 있게." 이어서 "이미 만들어 둔 horizon_bot_beta의 알고리즘이나 매매법을 참고해서 스코어링하는 건 어떤지도 확인해 봐."

이 문서는 설계안이다. 코드는 아직 쓰지 않았고, 점수·기록·판정은 바뀌지 않았다. 끝의 "정할 것"에 답을 받은 뒤 만든다.

## 1. 결론

**새 코인 점수를 만들지 않고, horizon_bot_beta가 이미 등록해 기록 중인 점수(α)를 그대로 가져다 보여 주는 것을 권한다.**

- 그 프로젝트는 같은 과거 자료(2022-01 ~ 2026-08)로 이미 17번 시험했다. 여기서 주식식 점수를 새로 만들어 같은 과거로 맞추면 18번째가 되고, 근거가 더 약한 점수가 하나 더 생길 뿐이다.
- 한 화면에 코인 점수가 둘이면 서로 어긋날 때 무엇을 믿을지 알 수 없다.
- 터미널이 더할 수 있는 것은 점수가 아니라 **보여 주는 방식**이다: 시장 선택(미국/한국/코인), '오늘' 목록, 비서의 설명, 근거와 한계의 표시.

## 2. horizon_bot_beta에서 확인한 것

읽은 곳: `~/Projects/horizon_bot_beta`의 `README.md`, `docs/QUANT_ARCHITECTURE_KO.md`, `docs/research/quant_explore.md`, `direction_result_v16.md`, `direction_result_v17.md`, `direction_preregistration_v18.md`, `research/alpha.py`, `runtime/predictor/`의 파일 형식. 그 프로젝트의 파일은 고치지 않았다.

| 항목 | 내용 |
|---|---|
| 대상 | 바이낸스 USDT 무기한 선물. 매달 1일에 그 전 1년 거래대금 상위 30개를 다시 고름 |
| 주기 | 4시간봉 마감마다 |
| 점수 α | 앞으로 7일 동안 대상의 중간 코인보다 몇 % 더 오를지. 신호 셋(자금조달비, 낮은 변동성, 낮은 베타)의 순위를 합쳐 매달 다시 학습 |
| 기록 | v15 그림자 장부(시장 중립, 판정 2027-05-15), v18 점수 1위 코인 가상 장부(2026-11-21 등록). 주문 없음 |

**신호 탐색에서 나온 것 (이미 본 자료, 증거가 아니라 후보 고르기였다):**

| 신호 | 7일 IC | 여섯 해의 방향 | 읽기 |
|---|---:|---|---|
| 낮은 베타 | +0.111 | 모두 + | 오래 감 |
| 낮은 변동성 | +0.110 | 모두 + | 오래 감 |
| 자금조달비(캐리) | +0.057 | 모두 + | 오래 감 |
| 반전(4시간·1일) | 4시간에서 +0.04, 7일에는 0 근처 | 들쭉날쭉 | 있지만 너무 빨리 사라져 비용을 못 넘음 |
| 모멘텀(1주·4주) | −0.027, −0.007 | 대부분 − | 큰 코인 사이에서는 거꾸로 작동 |

주식 터미널의 스윙 점수처럼 추세·모멘텀·돌파를 높이 치는 점수를 코인에 그대로 옮기면, 이 기록에 따르면 **거꾸로 가는 신호를 높이 치게 된다.** 새 점수를 만들지 말자는 가장 큰 이유다.

**돈으로 본 결과:**

- v16 (점수 1위 코인 하나를 롱): −62.7%. 같은 기간 대상 30개 동일 비중은 −79.2%, BTC 보유는 +40.2%. 점수 1위는 무작위로 섞은 점수의 93%보다 나았지만 미리 정한 기준(95%)에 못 미쳤다. 판정 `NO_TOP_COIN_EDGE`.
- v17 (시장 방향을 넣음): 시장 방향 예측과 실제의 상관이 −0.08. 판정 `NO_MARKET_TIMING_EDGE`.
- 정리하면 **α는 "다른 코인보다 나을지"를 약하게 가리지만 "오를지"는 가리지 못한다.** 시장이 내리면 점수 1위도 내린다.

## 3. 그 점수를 터미널에 쓸 때 꼭 붙여야 하는 단서

1. **상대 순위다.** 화면과 비서의 모든 문장에 "대상 30개 안에서의 순위이고, 오를지를 말하지 않는다"가 들어간다. 주식의 매수 후보 구간(70점)은 쓰지 않는다.
2. **선물 기준이다.** α는 선물을 들고 자금조달비를 내거나 받은 뒤의 수익으로 잰 값이다. 현물(업비트 원화 등)을 사는 사람은 자금조달비를 받지 못한다. 캐리 신호의 효과 일부는 현물에서는 생기지 않는다. 현물 기준으로는 확인된 적이 없다.
3. **판정 전이다.** v15는 2027-05-15에, v18은 그 등록 문서대로 판정한다. 터미널은 그 기록을 들여다보거나 따로 다시 시험하지 않는다.
4. **4시간마다 바뀐다.** 터미널의 주식 점수는 하루 한 번이다. 코인 화면은 "몇 시 마감 기준"을 항상 적고, 예측기가 멈춰 오래된 값이면 오래됐다고 표시한다(주식과 같은 규칙: 오래된 자료를 새것처럼 보이지 않는다).

## 4. 구조

```
horizon_bot_beta 예측기 (이미 돌고 있음: 공개 시세 수집, α 계산, 가상 장부)
        │  runtime/predictor/ 의 파일 (읽기만)
        ▼
터미널 terminal/coin/bridge.py  ──▶  /api/coin/*  ──▶  화면(시장 = 코인), 오늘 목록, 비서
```

- **읽기 전용 다리.** 터미널은 예측기가 쓰는 파일만 읽는다: `shadow_alpha.jsonl`(코인별 α), `status.json`(마지막 계산 시각), 코인별 4시간봉(`*.bars.npy`)과 자금조달비(`*.funding.npy`). 그 프로젝트의 폴더 위치는 `.env`의 `HORIZON_BOT_DIR`로 받는다. 없거나 읽지 못하면 "자료 없음"으로 보인다.
- **터미널은 코인 자료를 직접 받지 않는다.** 새 자료 출처가 생기지 않으므로 약관·robots 문제도 새로 생기지 않는다(수집은 그 프로젝트가 거래소 공개 시세로 이미 하고 있다).
- **주문 없음.** 터미널에는 지금도 주문 기능이 없고, 코인에서도 만들지 않는다. 실거래 여부는 horizon_bot_beta 쪽에서 사용자가 직접 켜는 것이고 터미널과 무관하다.
- 두 프로젝트를 한 코드로 합치지 않는다. 터미널의 원칙(무료 공개 자료, 주문 없음)과 봇의 성격이 다르다.

대안과 고르지 않은 이유:

| 대안 | 고르지 않은 이유 |
|---|---|
| 터미널 안에 α를 다시 구현 | 같은 계산이 두 곳에 생겨 언젠가 어긋난다 |
| 주식식 새 점수(추세·모멘텀 등) | 2절의 기록에서 거꾸로 가는 신호. 근거 없는 점수가 하나 더 생김 |
| 터미널이 거래소에서 직접 받아 새로 계산 | 새 출처의 약관 확인, 수집·저장·감시 코드가 통째로 필요. 얻는 것은 같은 숫자 |

## 5. 화면과 점수의 모양

**시장 선택:** 위의 버튼이 미국 / 한국 / 코인이 된다. 코인을 고르면 쓰지 않는 탭(거시, 모델, 연구실의 주식 부분)은 숨긴다.

**코인 순위 화면 (점수 묶음):**

| 열 | 내용 |
|---|---|
| 순위 | 대상 30개 안에서의 α 순위 |
| 기대 상대수익 | α를 %로(7일, 대상의 중간 대비). 왕복 비용 0.20%보다 큰지 표시 |
| 신호 세 가지 | 자금조달비, 변동성, BTC 베타의 실제 값과 대상 안에서의 위치 |
| 기준 시각 | 몇 시 마감의 계산인지, 얼마나 지났는지 |

- 0~100 점수로 보이게 하려면 α의 백분위를 쓴다(1위 100, 꼴찌 0). 주식 점수와 뜻이 다르므로 이름을 "상대 순위 점수"로 달리한다.
- 가격은 USDT 기준(바이낸스 선물)이다. 원화 가격과 김치 프리미엄은 2단계(아래)에서 다룬다.

**시장 상태(코인):** BTC가 200일 평균 위인지, 대상 30개 중 200일 평균 위 비율, 평균 자금조달비, BTC 도미넌스(예측기가 이미 받는 값), 변동성 위치. **참고 표시로만** 둔다. v17에서 시장 방향 예측이 맞지 않았다는 사실을 같이 적는다.

**오늘 목록과 비서:** 지금 구조를 그대로 쓴다. 코인용 질문 예: "BTC 점수 왜 이래?"(α를 신호 셋으로 나눠 실제 값과 함께), "코인 상위는?", "코인 시장 상태 어때?", "이 점수 믿어도 돼?"(2절과 3절의 내용).

## 7. 정할 것

1. **다리 방식으로 갈지.** (권함) 아니면 터미널에 코인 엔진을 따로 만들지.
2. **실제로 거래하려는 곳.** 업비트 현물인지, 바이낸스 선물인지. 현물이면 3절 2번(자금조달비를 받지 못함)이 그대로 해당하고, 화면에 그 문장을 더 크게 둔다.
3. **대상.** horizon_bot_beta의 30개 그대로인지. 업비트의 다른 알트코인은 그 점수의 대상이 아니라 점수를 낼 수 없다.
4. **계좌.** 포트폴리오 탭에 코인 계좌(USDT 또는 원화)를 따로 둘지. 두지 않으면 코인은 보유 점검과 주문 계획 없이 순위와 설명만 보인다.

## 8. 자료 출처에 대해 확인한 것과 못 한 것

- 바이낸스 공개 보관소(data.binance.vision)와 공개 시세 API: horizon_bot_beta가 이미 쓰고 있다. 바이낸스 안내에는 시세 자료로 유료 서비스나 자료 재판매를 하는 것을 금지한다는 내용이 있다(2022년 안내, 지금 약관 본문은 확인하지 못함). 개인이 자기 화면에서 보는 용도와는 다르지만, 이 프로그램을 남에게 팔거나 자료를 다시 배포하면 해당될 수 있다.
- 업비트: 시세 조회 API는 키 없이 쓰는 공개 API라고 두나무가 안내했다. Open API 이용약관이 따로 있고 "프로그램 유상 판매 불가" 공지가 있다. 요청 수 제한의 정확한 숫자와 약관 본문은 확인하지 못했다. 2단계 전에 읽는다.

## 9. 구현 기록 (2026-11-21, 사용자 답 "다리방식으로 해")

1단계를 만들었다. 정할 것 2~4는 답을 받지 않아 기본값으로 했다: 대상은 예측기의 30개 그대로, 코인 계좌는 두지 않음(순위와 설명만), 거래할 곳을 모르므로 현물 단서를 항상 보인다.

- `terminal/coin_bridge.py`: 예측기 폴더(`.env`의 `HORIZON_BOT_DIR`, 없으면 `~/Projects/horizon_bot_beta`)의 `shadow_alpha.jsonl`, 코인별 `*.bars.npy`, `*.funding.npy`만 읽는다. 쓰지 않는다. 그 프로젝트의 가상 장부 파일(잔고, 비중)은 읽지 않는다.
- 점수를 매긴 마감 시각까지의 봉만 쓴다(그 뒤의 봉은 보지 않는다). 변동성과 베타는 그 프로젝트의 정의(2주 반감기의 지수 가중, 60일 회귀)로 다시 계산한 참고값이다.
- 마지막 점수가 9시간(마감 두 번)보다 오래되면 "오래됨"으로 표시한다. 폴더나 파일이 없으면 이유를 적고 "자료 없음"으로 둔다.
- 화면: 위의 시장 버튼이 미국 / 한국 / 코인. 코인을 고르면 묶음이 "오늘"과 "코인" 둘만 보인다. 코인 탭은 순위표(기대 상대 폭, 가격, 1·7·30일, 자금조달비·변동성·베타와 대상 안에서의 위치)와 코인 시장(참고)이다.
- 비서: 코인 시장에서 질문 다섯 가지(상위, 시장 상태, 코인 하나의 노트, 믿어도 되나, 도움말)와 '오늘' 목록.
- 하지 않은 것: 원화 가격과 김치 프리미엄(2단계), 코인의 가격 범위(3단계), 코인 계좌, 텔레그램의 코인 줄.
