# 다섯 번째 audit: 블룸버그 터미널을 만드는 엔지니어의 눈 (2026-11-22)

사용자 요청: "더 업데이트 할만한게 없는지 블룸버그 터미널의 엔지니어 시선으로 audit 해봐라."

**방법.** 터미널 엔지니어는 점수가 맞는지가 아니라 **매일 쓰는 사람이 얼마나 빨리, 덜 틀리게 일하는가**를 본다. (1) 실제 서버에서 화면 요청 16가지의 첫 응답과 두 번째 응답 시간을 쟀다. (2) 첫 화면이 느린 곳을 프로파일러로 찾았다. (3) 화면 코드 전체를 따로 검토시키고, 그중 결함 하나를 코드로 다시 확인해 고쳤다. (4) 잘못 친 종목 코드가 어떻게 되는지 직접 넣어 봤다. 점수와 기록은 건드리지 않았다.

조건은 그대로다: 무료 공개 자료(일봉), 이 기기 안에서만, 주문 없음. 실시간 호가나 틱 자료가 필요한 기능은 대상에서 뺐다.

## 한 줄 결론

**자료와 계산은 터미널 수준인데, 손이 닿는 길이 아직 웹 페이지 수준이다. 고칠 것은 대부분 새 자료가 아니라 이미 있는 것을 더 빨리 꺼내는 일이다.**

## 1. 속도

| 화면 요청 | 서버를 다시 켠 뒤 첫 응답 | 두 번째 |
|---|---:|---:|
| 오늘 (미국) | **8.4초** | 0.34초 |
| 오늘 (한국) | **5.2초** | 0.23초 |
| 거시 | 3.5초 | 0.02초 |
| 업종 순환 | 3.0초 | 0.03초 |
| 차트, 종목 정보, 업종 비교 | 0.2~0.5초 | 0.03초 이하 |
| 나머지 9가지 | 0.07초 이하 | |

- **첫 화면이 가장 느리다.** 프로파일러로 따로 재면 '오늘'을 처음 만드는 데 3.2초가 걸리고, 그중 2.5초를 "상위 3종목" 한 줄을 위해 추적 보고서 전체를 다시 만드는 데 쓴다(22일치, 516종목의 가격을 다시 읽음). 서버를 막 켠 뒤에는 다른 준비 작업과 겹쳐 8.4초까지 늘어난다. 화면에 필요한 것은 오늘의 세 종목 이름뿐이다. 서버가 켜질 때와 매일 작업이 끝날 때 미리 만들어 두면 첫 화면이 바로 뜬다.
- **점수 탭은 들어갈 때마다 처음부터 다시 그린다.** 약 600KB짜리 점수 파일을 매번 다시 받고, 펼쳐 둔 줄과 스크롤 위치를 잃는다. 스윙/장기를 바꿀 때도 같은 파일을 다시 받는다(그 파일에 둘 다 들어 있다).
- **탭 일곱 개가 바꿀 때마다 다시 받는다.** 자료는 하루에 한 번 바뀌므로 스캔 날짜가 같으면 다시 받을 이유가 없다.

## 2. 종목 찾기

- **잘못 친 코드에 제안이 없다.** `APPL`을 넣으면 화면 넷이 2~3초씩 바깥에 물어본 뒤 "없음"을 띄운다. 비서도 "스캔 대상이 아닌 종목"이라고만 한다. 대상 804종목의 코드와 이름이 이미 기기에 있으므로 "AAPL(Apple)을 찾으셨나요?"는 바깥에 묻지 않고 답할 수 있다.
- **잘못 친 코드가 최근 종목에 저장된다.** 그 뒤 명령 창의 최근 목록과 비교 화면의 기본값에 계속 나온다.
- **미국은 이름으로 찾을 수 없다.** 한국은 회사명 검색이 있고 미국은 코드만 받는다. "apple"을 넣으면 코드 APPLE로 읽는다.

## 3. 명령 창과 키보드

- 명령 창(⌘K)은 탭 이동, 시장 전환, 종목 열기, 비교, 한국 이름 검색, 비서 질문을 받는다. 좋은 출발이다.
- **"종목 + 기능"이 없다.** 블룸버그의 핵심은 `AAPL` 다음에 기능을 치는 것이다. 지금은 "AAPL 점수"를 쳐도 종목 화면이 열린다(비교만 따로 처리돼 있다).
- **동작 명령이 없다.** 지금 수집, 관심종목에 추가, 차트 기간, 화면 색은 마우스로만 된다.
- **표의 줄을 키보드로 고를 수 없다.** 순위 줄, 카드, 정렬 머리글이 모두 클릭 전용이다.
- **M 키 하나가 입력하던 것을 지운다.** 입력칸 밖에서 M을 누르면 시장이 바뀌면서 모든 탭이 지워진다. 반쯤 적은 매매 일지도 사라진다.

## 4. 화면 사이의 연결

- **(고침) 조건 검색의 줄을 눌러도 아무것도 나오지 않았다.** 점수 카드를 숨겨진 화면에 그리고 있었다. 이제 카드가 보이는 화면으로 넘어간다.
- **종목이 탭을 따라가지 않는다.** 종목 화면에서 AAPL을 보다가 점수 탭, 알림, 수량 계산으로 가면 코드를 다시 쳐야 한다. 종목 화면에는 점수로 가는 버튼이 없고, 점수 카드에는 종목 화면으로 가는 링크가 없다.
- **주소에 남는 것이 탭과 종목뿐이다.** 시장, 점수 화면의 보기, 차트 기간, 비교 목록, 조건 검색의 조건은 새로 고치면 사라진다.

## 5. 자료의 날짜와 상태 표시

대부분의 화면은 기준일과 출처, "오래됨" 표시를 잘 보여 준다. 빠진 곳이 있다.

- 받기에 실패했는데 **"아직 기록이 없습니다"**로 나오거나 **빈 칸**으로 나오는 곳이 점수 탭에 여럿 있다. 실패와 없음은 다른 말이다.
- 종목 화면의 큰 가격에 날짜와 "오래됨" 표시가 없다.
- 머리글이 **"QSF 1.1"**인데 지금 공식은 QSF-1.4.1이다.
- 시각이 화면에 따라 한국 시각과 UTC로 섞여 나온다.
- 오류 문구 가운데 다섯 가지만 한국어이고 나머지는 코드 그대로 나온다(오늘 추가한 `FORBIDDEN_HOST` 포함).

## 6. 표와 차트

- 정렬은 업종 비교와 조건 검색에만, CSV 내보내기는 조건 검색에만 있다. 보유 종목, 매매 일지, 순위는 내보낼 수 없다.
- 차트는 기간 세 가지와 고정된 이동평균뿐이다. 로그 눈금, 십자선, 확대가 없고, **실적 발표일·공시·내 매매·손절과 목표를 차트에 찍지 않는다.** 자료는 모두 이미 있다.
- 한국 가격이 곳에 따라 소수 둘째 자리까지 나온다. 빈 값이 "—", "-", "없음" 세 가지로, 음수 부호가 두 가지로 섞여 있다.

## 7. 이미 가진 자료로 만들 수 있는데 화면에 없는 것

| 기능 | 쓰는 자료(이미 저장됨) |
|---|---|
| 차트 위의 사건 표시(실적일, 공시, 내 매매, 손절·목표) | 일봉, 공시 목록, 매매 일지 |
| 가격 위에 점수 이력 선 | 점수 원장(지금은 표로만) |
| 분기·최근 4분기 재무 표 | 분기 재무(지금은 연간만) |
| 자기 이력 PER·PBR 띠 그림, 실적일 반응 그림 | 오늘 만든 계산(지금은 노트의 글로만) |
| 오늘의 등락 상위, 52주 신고가, 거래량 급증 | 일봉 |
| 조건 검색에 수익률·시가총액·PER·ROE 열 | 원장의 비율 |
| 보유·관심 종목의 공시 모아 보기, 저장된 뉴스 보기 | 공시 목록, 뉴스 기록 |
| 거시 지표 두 개 겹쳐 보기 | 거시 계열 |

## 8. 값 대비 수고가 좋은 순서

1. **첫 화면 미리 만들기.** 서버가 켜질 때와 매일 작업 뒤에 '오늘'을 미리 계산한다. 8초가 0.3초가 된다.
2. **종목 찾기 고치기.** 코드·이름 자동 완성과 "이걸 찾으셨나요?", 미국 이름 검색, 잘못된 코드는 최근 목록에 넣지 않기.
3. **종목이 탭을 따라가게.** 한 번 연 종목이 점수·알림·수량 계산에 채워지고, 주소에 `#탭/종목`으로 남게.
4. **점수 탭을 다시 그리지 않기.** 받은 점수 파일을 스캔 날짜가 바뀔 때까지 쓴다.
5. **"종목 + 기능" 명령과 동작 명령.** `AAPL 점수`, `AAPL 노트`, `AAPL 알림`, `수집`, `관심 추가`.
6. **실패 표시 통일.** 실패는 실패로, 없음은 없음으로. 오류 문구 한국어화, 머리글의 버전 표시.
7. **표 공통 기능.** 모든 표에 정렬과 CSV·복사, 키보드로 줄 이동.
8. **차트.** 사건 표시, 로그 눈금, 십자선, 한국 가격 표기.
9. **M 키로 입력이 지워지지 않게.**

1~4번은 새 자료가 필요 없고 점수와 무관하다. 5~9번도 같다. 결정이 필요한 것은 없고, 만들지 말지만 정하면 된다.

## 오늘 고친 것

- 조건 검색의 줄을 누르면 점수 카드가 보이는 화면으로 넘어가도록 고쳤다(4절).

화면 코드의 세부 위치(파일과 줄)는 별도 검토의 보고에 있고, 이 문서의 4절 첫 항목과 1·2절의 수치는 내가 직접 확인했다. 나머지 3·5·6절은 검토 보고를 옮긴 것이다.
